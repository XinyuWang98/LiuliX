# 🚀 启动新任务/功能工作流 (/start_task)

在开始**任何**新任务或功能时，请遵循此流程以确保符合全局用户规则。

## 1. 规划与分析 (Planning & Analysis)
1.  **理解需求**：仔细阅读用户请求。
2.  **复用检查**：使用 `grep_search` 搜索现有代码，查找可复用的组件/Hook/逻辑（规则 #17）。
3.  **查阅文档**：阅读 `docs/` 下与任务相关的特定文档（例如 `01-架构设计/`）。
4.  **制定计划**：
    *   创建或更新 `implementation_plan.md`。
    *   **关键**：提前规划文件行数限制（规则 #11）。如果文件可能超过 500 行，**立即**规划拆分方案。
    *   **关键**：规划 `useEffect` 依赖和状态保留策略（规则 #12）。

## 2. 文档更新 (规则 #7 & #16)
1.  **更新概览**：更新 `docs/00-必读/01-核心-项目概览与现状.md`。
2.  **更新任务表**：更新 `task.md`。
3.  **确认文档变更**：如果需要修改其他设计文档，**必须先询问用户**（规则 #16）。

## 3. 开发循环 (Implementation Loop)
1.  **编写代码**：
    *   **日志**：使用 `logger` 工具记录所有日志（规则 #15）。
    *   **文案**：所有文本必须使用 `t('key')`（规则 #2）。
    *   **样式**：所有样式必须使用 CSS 变量（规则 #1），禁止硬编码。
2.  **验证行数**：检查修改后的文件是否超过 500 行。如果超过，**停止并拆分**（规则 #11）。
3.  **验证 i18n**：如果添加了新 Key，**立即**更新 `src/types/i18n.ts`（规则 #21）。

## 4. 验证 (Verification)
1.  **全链路脚本验证**: 运行 `npm run verify` 以快速检查核心逻辑（Prompt, Parser）。
2.  **浏览器测试**：打开浏览器，刷新页面，检查控制台 (Console) 和网络 (Network)（规则 #2）。
2.  **错误检查**：修复 IDE 中的所有红线报错（规则 #1）。

// turbo
5. **标记完成**：更新 `task.md` 将项目标记为完成。
