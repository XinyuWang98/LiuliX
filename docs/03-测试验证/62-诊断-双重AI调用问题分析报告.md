## 🎯 根本原因定位

### 原因 1：React StrictMode 双重渲染

**证据 1**：[`src/main.tsx`](file:///Users/catherinewang/Documents/GitHub/LiuliX/src/main.tsx#L23-L25)

```tsx
// Line 23-25
<React.StrictMode>
    <App />
</React.StrictMode>
```

**React StrictMode 行为**：
- 在**开发模式**下，会故意双重调用组件和 Effect
- 用于检测副作用和不良实践
- **仅影响开发环境，生产环境单次调用**

---

### 原因 2：useInsightRefresh 防重逻辑不完善

**当前实现**：[`useInsightRefresh.ts`](file:///Users/catherinewang/Documents/GitHub/LiuliX/src/hooks/useInsightRefresh.ts#L98-L102)

```typescript
// Line 98-102
if (!depsChanged && loadedOnceRef.current) {
    logger.warn('AI洞察', 'Strict Mode或重复状态更新已拦截');
    return;  // 应该阻止重复调用
}
```

**问题**：
- ✅ 逻辑看似正确（依赖未变 + 已加载 = 跳过）
- ⚠️ 但在 StrictMode 下，**第一次双重渲染时 `loadedOnceRef` 还是 false**
- ⚠️ 所以前两次调用都会执行，导致双重 AI 请求

---

- ⚠️ 可能触发额外的组件重新挂载

### 方案 B：优化防重逻辑（推荐）

**操作**：在 `useInsightLoaderV2.ts` 中添加调用去重

```typescript
const loadInsights = async (...) => {
    // 🆕 防止 StrictMode 双重调用
    const callId = `${tableName}_${Date.now()}`;
    if (currentCallRef.current === callId) {
        logger.warn('AI洞察', '检测到重复调用，已跳过');
        return [];
    }
    currentCallRef.current = callId;
    
    // ... 原有逻辑
};
```

**优势**：
- ✅ 保留 StrictMode 的好处
