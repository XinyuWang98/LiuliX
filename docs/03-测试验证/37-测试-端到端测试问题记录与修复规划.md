### 🟡 [UX] 问题 4: "暂无假设卡片" 提示出现时机不当
**状态**: 待修复
**反馈来源**: 用户反馈

#### 问题描述
文件上传后立即显示 "暂无假设卡片" ⚠️ 提示，给用户造成“出错了”的误解。实际上此时后台可能正在加载模型或准备数据。

#### 根本原因分析
`InsightChainFlow.tsx` 中的渲染逻辑：
```tsx
{!isLoading && hypotheses.length === 0 && ( ... error state ... )}
```
在组件初始挂载时（或文件刚切换时），`isLoading` 可能尚未被 Hook 置为 `true`，或者是 `hypotheses` 初始化为空数组。
此外，`useInsightLoaderV2` 的初始状态可能默认为 `false`，直到 `loadInsights` 被调用。

#### 修复规划
-   **优化 Loading 状态**: 确保 Hook 在初始化阶段（检查 cache 或准备数据时）立即返回 `isLoading: true`。
-   **引入中间状态**: 增加 `isInitializing` 状态，在数据未就绪前显示 "等待数据准备..." 或骨架屏，而非错误提示。
-   **文案优化**: 将 "暂无假设卡片" 及其警告图标改为更中性的文案（如 "准备生成洞察..."），仅在明确失败或长时间无结果后才显示警告。

### 🟡 [UI] 问题 5: AI建议与规则建议卡片样式不一致
**状态**: 待修复
**反馈来源**: 用户截图

#### 问题描述
AI 建议卡片（丰富、绿色推荐度）与 规则建议卡片（简单、黄色推荐度）在视觉上差异过大，缺乏一致性。

#### 根本原因分析
两者共用 `SuggestionCard.tsx` 组件，但：
1.  **标签差异**: CSS 类 `.ai` vs `.rule` 导致标签颜色不同（这是预期的）。
2.  **内容差异**: AI 建议通常包含较长的 `reason` 文本，而规则建议可能只有简短的描述或空描述，导致卡片高度塌陷或显得单薄。
3.  **颜色差异**: 推荐度颜色硬编码（AI >80% Green, Rule 70% Orange），导致视觉重心不同。

#### 修复规划
-   **样式统一**: 
    -   统一使用 Glassmorphism 风格背景。
    -   强制卡片最小高度 (Min-Height) 以对齐视觉。
-   **内容丰富化**: 
    -   为规则建议生成更友好的 `reason` 文案（如 "基于缺失率规则自动检测"）。
    -   如果 `reason` 为空，显示默认占位符。
-   **视觉对齐**: 调整 `.rule` 标签样式，使其与 AI 标签在尺寸和字体上完全一致，仅保留颜色区分。

### 🟢 [UI] 问题 6: 表格列宽在少列时未自动撑开
**状态**: 待修复
**反馈来源**: 用户截图

#### 问题描述
当数据列数较少（如11列，总宽未填满屏幕）时，表格右侧出现大片空白区域。用户希望此时能自动撑开每一列以适应剩余空间，但需确保列数较多时仍保持默认宽度和水平滚动（不影响默认展示前10列的设置）。

#### 根本原因分析
`VirtualDataGrid.tsx` 中可能使用了固定列宽或基于内容的计算宽度，但未包含“最小总宽度”逻辑。
react-window 的 `VariableSizeGrid` 通常按需渲染，若列总宽小于容器宽，默认不会自动拉伸。

#### 修复规划
-   **方案**:
    1.  计算所有列的预估总宽度 `totalEstimatedWidth`。
    2.  获取容器宽度 `containerWidth`。
    3.  如果 `totalEstimatedWidth < containerWidth`，计算剩余空间 `remain = containerWidth - totalEstimatedWidth - scrollbarWidth`。
    4.  将剩余空间平均分配给每一列（`columnWidth + remain / colCount`），或者加权分配。
    5.  确保此逻辑仅在总宽不足时触发，列多时维持原状。
