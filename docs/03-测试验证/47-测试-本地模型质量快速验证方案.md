# 47-测试-本地模型质量快速验证方案

> **目标**: 在不修改 LiuliX 核心代码的前提下，验证 `Transformers.js` / `WebLLM` (本地小模型) 是否有能力承担 **L1 洞察推荐** (Insight Recommendation) 的任务。

## 1. 核心发现与验证思路

经深度代码审计 (`explorer_general.zh.ts`)，LiuliX 的核心 AI 逻辑是 **"主动推荐" (Proactive Recommendation)**。
*   **输入**: 数据集摘要 (JSON) + 历史记录。
*   **输出**: 推荐列表 (JSON,包含 `promptId`, `params`, `reason`)。
*   **执行**: 前端通过 `inflater.ts` 将推荐结果映射为硬编码的 Python 模板 (`worker_*.ts`)。

**结论**: AI **不需要写 Python 代码**，也不仅仅是做分类，而是要进行 **"基于数据的推理" (Data-Driven Reasoning)** 并输出 **"结构化 JSON"**。

**验证公式**:
$$ \text{小模型能根据数据统计推荐正确图表} + \text{输出合规 JSON} = \text{本地化成功} $$

## 3. 核心验证：L1 推荐能力 (P0)

### 3.1 测试目标
验证 7B/3B 级别的小模型，能否读懂数据统计信息 (`df_summary`)，并推荐出"靠谱"的分析维度。

### 3.2 Golden Dataset (L1 推荐场景)
我们需要构造几个典型的数据集摘要，并定义"正确"的推荐方向。

**示例 Case 1: 趋势分析推荐**
```json
{
  "scenario": "时序数据",
  "df_summary": {
    "rowCount": 365,
    "columns": [
      { "name": "date", "type": "datetime", "min": "2023-01-01", "max": "2023-12-31" },
      { "name": "sales", "type": "numeric", "mean": 1000, "std": 500 } //高波动
    ]
  },
  "expected_recommendations": [
    { "promptId": "worker-trend-v1", "params": { "date_col": "date", "value_col": "sales" } }
  ]
}
```

**示例 Case 2: 相关性推荐**
```json
{
  "scenario": "强相关数据",
  "df_summary": {
    "rowCount": 1000,
    "columns": [
      { "name": "sq_ft", "type": "numeric" },
      { "name": "price", "type": "numeric", "corr_with_sq_ft": 0.85 } // 强相关
    ]
  },
  "expected_recommendations": [
    { "promptId": "worker-correlation-v1", "params": { "col_x": "sq_ft", "col_y": "price" } }
  ]
}
```

### 3.3 验证脚本 (Mock L1 Executor)
使用 Python 脚本调用 HF API，模拟 `explorer_general` 的工作流。

```python
import requests
import json

API_URL = "https://api-inference.huggingface.co/models/Qwen/Qwen2.5-Coder-7B-Instruct"
headers = {"Authorization": "Bearer hf_xxxx"}

# 模拟 explorer_general.zh.ts 中的 Prompt
SYSTEM_PROMPT = """
你是一个数据科学家。分析数据摘要，推荐 1 个最值得分析的方向。
可用工具: 
- worker-trend-v1 (params: date_col, value_col)
- worker-correlation-v1 (params: col_x, col_y)

输出 JSON: {"recommendations": [{"promptId": "...", "params": {...}, "reason": "..."}]}
"""

def test_l1_recommendation(case):
    prompt = f"{SYSTEM_PROMPT}\n\n数据摘要:\n{json.dumps(case['df_summary'])}"
    
    response = requests.post(API_URL, headers=headers, json={
        "inputs": prompt,
        "parameters": {"max_new_tokens": 512, "return_full_text": False}
    })
    
    try:
        content = response.json()[0]['generated_text']
        # 尝试清理 markdown 标记
        json_str = content.replace("```json", "").replace("```", "").strip()
        result = json.loads(json_str)
        
        rec = result['recommendations'][0]
        expected = case['expected_recommendations'][0]
        
        # 验证 PromptID 和 参数
        is_id_match = rec['promptId'] == expected['promptId']
        is_params_match = all(rec['params'][k] == expected['params'][k] for k in expected['params'])
        
        print(f"场景 [{case['scenario']}]: {'✅' if (is_id_match and is_params_match) else '❌'}")
        if not (is_id_match and is_params_match):
            print(f"  预期: {expected}")
            print(f"  实际: {rec}")
            
        return is_id_match and is_params_match
    except Exception as e:
        print(f"❌ 解析失败: {e}\n  Raw: {content}")
        return False

# 运行测试

```

## 4. 成功标准 (Pass Criteria)

### 🔥 L1 推荐质量
*   **JSON 格式正确率 > 90%**: 必须能被 `JSON.parse` 解析，不能少括号或逗号。
*   **推荐逻辑准确率 > 80%**: 对于明显的特征（如强相关、时间序列），必须推荐正确的分析工具。
*   **参数映射正确率 > 90%**: 必须准确将列名填入 params。

---

## 5. 为了"求稳"的降级策略

如果 7B 模型在 JSON 格式化上表现不稳定（常见问题），我们可以采用 **Constrained Generation (语法约束)**。

*   **技术方案**: WebLLM 支持 `Response Format` (JSON Schema) 强制约束。
*   **Plan B**: 如果 Prompt 工程搞不定，就上 JSON Schema 约束，强制模型只能吐出符合结构的 JSON。
