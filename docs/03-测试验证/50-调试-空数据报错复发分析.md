# 🐛 调试报告：空数据报错复发分析 (Empty Data Error Analysis)

> **关联任务**: [空数据报错复发](task.md)
> **状态**: ✅ 已定位根因 (Root Cause Identified)

## 1. 问题描述 (Issue Description)

在对 `mega_ecommerce_600k.csv` 进行测试时，"了解不同支付方式的使用频率分布" 这一洞察再次触发了以下错误：

```text
ValueError: 绘图被拦截: 检测到数据为空 (len=0)。请检查过滤条件或数据加载。
```

该错误曾在之前出现过，并通过修复 `src/services/skills/modeExecutor.ts` 中的类型转换逻辑得到解决。然而，此次复发表明存在尚未覆盖的边缘情况或新的触发源。

## 2. 调查过程 (Investigation Process)

### 2.1 检查底层加载逻辑 (`modeExecutor.ts`)
虽然此前已修复了激进的类型转换逻辑，但首先需要排除是否该文件在处理 `mega_ecommerce_600k.csv` 的特定数据时仍然存在问题。
- **检查**: 复查代码，确认逻辑为 `if not converted.isna().all(): _master_df[col] = converted`。
- **结论**: 该逻辑是安全的。对于全字符串列（如 `payment_method`），`to_numeric` 会产生全 NaN，导致 `if` 条件为假，从而保留原始字符串数据。

### 2.2 验证特定数据集内容
怀疑数据集中是否存在混合类型导致判断失误。
- **操作**: 编写脚本 `scripts/verify_numeric_conversion.py` 对 `product_category`, `payment_method`, `region`, `status` 等列进行模拟转换测试。
- **结果**:
    ```text
    Checking column: payment_method
    Non-NaN count after to_numeric: 0
    ✅ Safe: Column 'payment_method' is all NaNs after coercion (isna().all() is True).
    ```
- **结论**: 数据集本身和加载逻辑没有问题，字符串被正确保留。

### 2.3 检查 Prompt 模板 (`worker-distribution-v1`)
追溯报错的洞察对应的 Prompt ID 为 `worker-distribution-v1`。检查其对应的模板文件 `src/services/prompts/library/l2/worker_distribution/worker_distribution.zh.ts`。

**发现关键代码缺陷**:
```python
# src/services/prompts/library/l2/worker_distribution/worker_distribution.zh.ts: Lines 43-44
column_name = {{column_name}}
col_data = pd.to_numeric(df[column_name], errors='coerce').dropna()  # 🚨 问题根源
```

该模板在 Python 代码层面执行了**无条件强制类型转换** (`pd.to_numeric` + `errors='coerce'`)，并立即丢弃了所有 NaN 值 (`dropna()`)。

## 3. 根因分析 (Root Cause Analysis)

1.  **二次破坏**: 尽管 `modeExecutor.ts` 正确地将 `payment_method` 作为字符串列传递给了 Python 环境，但在 Python 环境内部执行洞察代码时，Prompt 模板又做了一次**强制数值转换**。
2.  **逻辑缺失**: `worker-distribution-v1` 的描述声称支持 "数值列直方图或分类列柱状图"，但其实代码实现**完全缺失了分类数据的处理分支**。它假定所有输入都是数值。
3.  **执行链**:
    *   输入: `payment_method` (['Alipay', 'Credit Card', ...])
    *   `pd.to_numeric(..., errors='coerce')` -> 全部转换为 `NaN`
    *   `.dropna()` -> 结果为空 Series
    *   `ax1.hist(col_data)` -> 尝试对空数据绘图
    *   触发 `liulix-code-enhancer` 的空数据拦截规则 -> **报错**

## 4. 解决方案建议 (Recommended Solution)

需要修改 `worker_distribution.zh.ts`（以及对应的英文版），在 Python 代码模板中增加对数据类型的动态判断，实现真正的分支逻辑。

**建议修复代码 (Pseudocode)**:

```python
import pandas as pd
import numpy as np
import matplotlib.pyplot as plt

# ...

column_name = {{column_name}}

# 动态判断类型
if pd.api.types.is_numeric_dtype(df[column_name]):
    # 数值型处理逻辑 (直方图 + 密度图)
    col_data = df[column_name].dropna()
    # ... (原有绘图逻辑)
else:
    # 分类型处理逻辑 (Top 10 条形图)
    col_data = df[column_name].value_counts().head(10)
    fig, ax = plt.subplots(figsize=(10, 6))
    col_data.plot(kind='bar', ax=ax, color='#3498db')
    ax.set_title(f'{column_name} Top 10 分布')
    # ...
```
