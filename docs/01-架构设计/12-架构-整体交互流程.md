# 用户交互时序图 (User Interaction Flow)

该文档梳理了 **DataPrism** 系统中“文件上传 > 数据清洗 > 数据洞察”的完整用户交互时序图。

**更新日志**：
- **v2**: 将核心服务拆分为独立泳道 (`DuckDB`, `QualitySvc`, `CleanSvc`, `AISvc`, `EvidenceStore`)，展示更细粒度的调用交互。

图表设计规范：
1.  **左侧 (User/UI)**：聚焦用户显式操作与界面反馈。
2.  **右侧 (Core Services)**：将逻辑层与具体的基础设施服务解耦，明确数据流向。
3.  **正交性**：所有交互线段水平且垂直，流程清晰。

## 完整时序图 (Detailed Service Interaction)

```mermaid
sequenceDiagram
    autonumber
    actor User as 用户 (User)
    box "前端应用层 (Frontend App)" #ffffff
        participant UI as 界面组件<br>(Components)
        participant Logic as 业务逻辑<br>(Hooks/Utils)
    end
    box "核心服务层 (Core Services)" #f9f9f9
        participant DB as DuckDB引擎<br>(DuckDBEngine)
        participant Quality as 质量服务<br>(DataQualityService)
        participant Clean as 清洗服务<br>(AICleaningService)
        participant AI as AI通用服务<br>(AIService)
        participant Store as 证据池<br>(EvidenceContext)
    end

    Note over User, Store: =========== 阶段一：文件上传 (Data Ingestion) ===========

    User->>UI: 1. 拖拽/选择文件
    activate UI
    UI->>Logic: FileUploader.handleFiles()
    activate Logic
    
    Logic->>DB: analyzeCSV(file)
    activate DB
    DB-->>Logic: 返回预检结果 (Strategy: SKIP/WARN)
    deactivate DB

    alt 策略=WARN (大文件)
        Logic-->>UI: 显示采样确认弹窗
        User->>UI: 2. 确认导入
    end

    Logic->>DB: ingestCSV(file)
    activate DB
    Note right of DB: 双表创建:<br>1. t_original (只读)<br>2. t_working (读写)
    DB-->>Logic: 入库成功 (TableName)
    deactivate DB
    
    Logic-->>UI: 更新全部文件状态
    deactivate Logic
    UI-->>User: 3. 渲染 DataViewer 数据表
    deactivate UI

    Note over User, Store: =========== 阶段二：数据清洗 (Data Cleaning) ===========

    User->>UI: 4. 进入 DataCleaner 视图
    activate UI
    UI->>Logic: useSuggestionGeneration (Init)
    activate Logic
    
    par 并行服务调用
        Logic->>Clean: generateAICleaningSuggestions()<br>(DuckDB数据采样 -> LLM)
        activate Clean
        Clean-->>Logic: 返回 AI 清洗建议列表
        deactivate Clean
    and 本地质量检查
        Logic->>Quality: assessQuality()<br>(规则引擎检查)
        activate Quality
        Quality-->>Logic: 返回健康度评分 (Score)
        deactivate Quality
    end

    Logic-->>UI: 渲染建议卡片 (SuggestionCard)
    deactivate Logic
    deactivate UI

    User->>UI: 5. 选中建议并点击“执行”
    activate UI
    UI->>Logic: useCleaningExecution.handleApply()
    activate Logic
    Logic->>Logic: sqlBuilder.buildCleaningSQL()
    
    Logic->>DB: query(Execute SQL)
    activate DB
    Note right of DB: UPDATE/DELETE<br>Target: t_working
    DB-->>Logic: 执行成功
    deactivate DB
    
    Logic->>Logic: useCleaningHistory.addHistory()
    Logic-->UI: 触发 Mutation 刷新数据
    deactivate Logic
    UI-->>User: 6. 视图更新 & 历史列表追加
    deactivate UI

    Note over User, Store: =========== 阶段三：数据洞察 (Data Insight) ===========

    User->>UI: 7. 展开“洞察链分析”模块
    activate UI
    UI->>Logic: InsightChainFlow (Mount)
    activate Logic
    
    Logic->>AI: generateHypotheses(columns)
    activate AI
    AI-->>Logic: 返回分析假设列表
    deactivate AI
    
    Logic-->>UI: 渲染 3 张假设卡片
    deactivate Logic
    deactivate UI

    User->>UI: 8. 点击某张假设卡片
    activate UI
    UI->>Logic: set ActiveHypothesis
    activate Logic
    
    Logic->>AI: (Optional) generateInitialNode
    activate AI
    Note right of AI: 自动生成初始图表节点
    AI-->>Logic: 返回 Node 数据
    deactivate AI
    
    Logic-->>UI: 渲染洞察节点 (InsightNode)
    deactivate Logic
    deactivate UI

    opt 用户深挖 (Deep Dive)
        User->>UI: 9. 输入指令并提交
        activate UI
        UI->>Logic: handleDeepDive()
        activate Logic
        Logic->>AI: generateInsight(instruction)
        activate AI
        AI-->>Logic: 返回新 Node (Chart/Code)
        deactivate AI
        Logic-->>UI: 追加显示新节点
        deactivate Logic
        deactivate UI
    end

    User->>UI: 10. 点击“采纳”按钮
    activate UI
    UI->>Logic: adoptChain()
    activate Logic
    
    Logic->>Store: EvidencePool.addItem(insightChain)
    activate Store
    Store-->>Logic: 状态更新确认
    deactivate Store
    
    Logic-->>UI: 更新全局 Context 状态
    deactivate Logic
    UI-->>User: 11. 证据栏徽标跳动 (+1)
    deactivate UI
```

## 服务职责定义

*   **DuckDBEngine**: 负责所有本地数据的存储、查询和物理表操作（Ingest, Query）。管理 `original` 和 `working` 双表生命周期。
*   **DataQualityService**: 客户端轻量级服务，直接基于部分数据进行规则计算（缺失率、重复率等），提供即时健康度反馈。
*   **AICleaningService**: 负责与 LLM 交互，提供复杂的数据清洗建议。包含 Prompt 构建、结果解析和格式化。
*   **AIService**: 通用 AI 服务，负责“分析假设生成”、“自由数据洞察”和“代码生成/解释”。
*   **EvidenceContext (Store)**: 全局状态容器，负责存储用户采纳的有价值分析片段（证据），供后续报告生成使用。
