## 2. 核心组件布局详解

### 2.1 树节点 (`InsightTreeNode`)
采用 **6行式标准布局**，确保信息密度与可读性的平衡。

*   **Row 1: Header (核心索引)**
    *   **合并设计**: 将设计稿中的 Row 1 (Title) 和 Row 2 (Metadata) 合并，Title 居左，Tags 居中/右，图标指示状态。
    *   **视觉**: Depth-0 节点有背景色和边框，子节点背景透明，仅通过左侧缩进区分层级。
*   **Row 3: Visualization (可视化)**
    *   **展示**: 图片直接作为 `img` 标签渲染，支持点击放大 (Zoom-in)。
*   **Row 6: DrillDownArea (下钻区)**
    *   **集成**: 作为节点内容的最后一部分，不再是独立的平级节点，而是父节点内容的一部分。
    *   **交互**:
        *   **推荐动作**: 展示为 `ActionChip`，点击即触发下钻。
        *   **自定义分析**: 内嵌在 `DrillDownArea` 中的折叠面板，点击设置图标展开。

### 2.2 连接线系统 (Visual Connection)
目前的连接线通过 CSS 伪元素实现：
*   **垂直线**: 位于 `Children Container` 左侧。
*   **水平线**: 位于每个子节点 Title 左侧。
*   **L型转角**: 最后一个子节点通过特定 CSS (`:last-child`) 截断垂直线，形成完美的 L 型闭合。

## 3. 交互逻辑现状
1.  **展开/折叠**: 点击 Header 上的 Chevron 图标切换 `isExpanded` 状态。折叠时隐藏 Body，包含图表、摘要、代码、下钻区和所有子节点。
2.  **下钻生成**:
    *   点击 Action Chip -> 触发 API -> 生成新节点数据。
    *   新节点直接 `push` 到当前节点的 `children` 数组中。
    *   UI 自动重绘，新节点出现在 `Children Container` 末尾。
3.  **加载反馈**: 局部 Loading，仅在生成的子节点位置显示 Loader，父节点无变化。

## 4. 与设计文档 (`28-设计-*.md`) 的差异验证
*   **一致性**: 核心“森林式下钻”、“卡片内 6 行布局”均已严格实现。
*   **优化点**: 实际代码中将 Header 和 Metadata 合并优化了垂直空间；自定义分析面板采用了更节省空间的折叠式设计。
