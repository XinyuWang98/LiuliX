# 组件渲染优先级分析

> [!NOTE]
> 本文档分析 DataPrism 当前组件架构的渲染优先级与性能现状，并提出优化建议。

## 1. 概述

当前应用采用 React 单页应用架构（SPA），核心交互围绕布局（LeftSidebar/AppContent）、数据展示（VirtualDataGrid）与 AI 交互（ExplorationFlow/AIWorkshop）展开。随着数据量增大和 AI 后台任务（清洗、洞察预加载）的引入，合理的渲染优先级控制变得至关重要。

## 2. 渲染优先级分级 (Priority Levels)

基于用户体验原则，我们将组件渲染划分为四个优先级等级：

### Lv1: 关键路径 (Critical) - 必须立即响应
阻塞用户操作的 UI，延迟会导致明显的"卡顿"感。
- **App Layout**: `App.tsx` (布局容器, 侧边栏切换)
- **Navigation**: `NavigationBar` (核心导航)
- **Input Response**: `FileUploader` (文件选择), `LeftSidebar` (文件点击切换)
- **Dashboard Visibility**: `ExplorationFlow` (主数据流容器)

### Lv2: 高优先级 (High) - 可见的交互反馈
用户关注的焦点区域，允许轻微但在 100ms 内的延迟。
- **Data Grid**: `VirtualDataGrid` (表格内容渲染) - *性能热点*
- **Active Tools**: `AIWorkshopTools` (右侧工具面板当前激活的 Tab)
- **Chat Input**: `ExplorationFlow` 底部输入框

### Lv3: 中优先级 (Medium) - 异步内容与指示器
数据加载、后台处理的反馈 UI。
- **Loading States**: `LoadingScreen`, 表格加载转圈
- **Charts/Vis**: `MiniHistogram`, `MiniBarChart` (表格头部的微型图表)
- **Toast Notifications**: 操作结果提示

### Lv4: 低优先级 (Low) - 后台任务与隐藏内容
用户不可见或非核心任务，应避免阻塞主线程。
- **Hidden Tabs**: 右侧边栏未激活的工具面板
- **Background Prefetch**: `LeftSidebar` 中的 `prefetchInsightsForFile` (AI 洞察预加载)
- **Off-screen Rows**: 虚拟滚动列表在视口外的部分

## 3. 现状深度分析

### 3.1 侧边栏与后台任务 (LeftSidebar)
- **现状**: 引入了 `ConcurrencyQueue` (limit=3) 来管理 AI 清洗建议的生成，并新增了**并行洞察预加载**。
- **优点**: 将计算密集型任务（DuckDB查询、AI推理）移出主渲染流，避免阻塞 UI。
- **风险**: `setProjects` 和 `setFileAIStatus` 的高频更新可能导致 `LeftSidebar` 及 `ProjectItem` 频繁重渲染。
    - *观察*: `ProjectItem` 未使用 `React.memo`，每次父组件状态更新都会导致所有列表项重绘。

### 3.2 虚拟数据表格 (VirtualDataGrid)
- **现状**: 使用手动分页 (Pagination) 和 DOM 虚拟化思想（手动计算渲染行），但未完全实现滚动虚拟化（Row Virtualization）。
- **性能瓶颈**: 
    - 包含大量微型可视化组件 (`MiniHistogram`)，每个 Header Cell 都在计算渲染。
    - **严重**: `VirtualDataGrid` 组件本身缺少 `React.memo` 包裹，且内部包含多个内联定义的子组件 (`NumericStatsPanel` 等)，导致每次父组件更新都会重新创建这些子组件函数。
- **Render Cost**: 列数较多时，表头渲染开销巨大。

### 3.3 探索流 (ExplorationFlow)
- **现状**: 基于 ID 的块列表 (`blocks`) 渲染。
- **优化点**: 
    - `renderContent` 每次渲染都重新生成 JSX，尽管 React 会 Diff，但传递给子组件的 props 对象（如 `aiSuggestions`）若引用不稳，会导致子组件无效重渲染。
    - `InsightChainFlow` 的初始化依赖于 `project.files[0]` 的深度属性访问，数据结构复杂。

## 4. 优化策略与建议

### 4.1 实施 React.memo 优化
针对高频更新的叶子组件进行 Memoization：
- [ ] **ProjectItem**: 仅在自身 props (isExpanded, status) 变化时渲染，忽略兄弟节点的 prefetch 状态变化。
- [ ] **VirtualDataGrid**: 表格数据未变时，禁止由父容器 resize 引发的无效重绘（除非 resize 导致布局剧变）。
- [ ] **MiniHistogram/MiniBarChart**: 这些纯展示组件非常适合 Memo，避免跟随表头频繁刷新。

### 4.2 渲染并发控制 (Concurrent Rendering)
- [ ] **React 18 Transitions**: 将 `setSearchQuery` (如果导致列表过滤滞后) 或后台任务引起的状态更新包裹在 `startTransition` 中，确保 Lv1 用户输入优先响应。
- [ ] **Deferred Value**: 对搜索结果列表使用 `useDeferredValue`。

### 4.3 状态隔离 (State Isolation)
- [ ] **AI Status 独立上下文**: 目前 AI 状态存在 `LeftSidebar` 内部 state 中。建议拆分为独立的 `AIStatusContext`，使得状态更新仅触发订阅该状态的微小组件（如 `StatusIcon`），而不触发整个 Sidebar 重绘。

### 4.4 虚拟化增强
- [ ] **真实虚拟滚动**: 对于 `VirtualDataGrid`，引入 `@tanstack/react-virtual` 或类似库，仅渲染视口内 DOM，目前即使是分页，如果列数过多 (Wide Table)，DOM 节点数依然庞大。

## 5. 结论

当前架构在功能上已实现逻辑解耦，但在渲染性能上存在**"组件粒度过粗"**和**"状态更新波及范围过大"**的问题。
- **短期改进**: 重点为 `ProjectItem` 和 `MiniHistogram` 添加 `React.memo`。
- **长期规划**: 将 AI 后台任务状态抽出为独立 Store (Zustand/Context)，实现细粒度更新。
