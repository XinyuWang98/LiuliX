# 分析报告交互增强方案 (Report Interaction Enhancement)

## 1. 需求背景 (Background)
用户需要在 **分析报告 (Report Workbench)** 中能够自由调整单元 (Cell) 的顺序。
目前 `ReportNotebook` 仅按添加时间顺序展示，无法通过拖拽调整位置，限制了用户的编辑体验。

## 2. 核心功能 (Core Features)

### 2.1 拖拽排序 (Drag and Drop)
*   **交互方式**: 用户在 "Notebook" (编辑) 模式下，按住 Cell 的拖拽手柄 (Drag Handle) 进行上下拖动。
*   **已签名锁定**: 如果报告已签名 (Signed)，则禁用拖拽功能。
*   **预览同步**: 拖拽完成后，"Preview" (预览) 模式下的内容顺序应立即同步更新。

### 2.2 视觉反馈
*   **拖拽中**: 被拖拽的 Cell 应有半透明或抬起阴影效果。
*   **占位符**: 目标位置应显示占位指示器。

## 3. 技术方案 (Technical Implementation)

鉴于项目技术栈，采用 **@dnd-kit** 库来实现，具有轻量、可访问性好、React Hooks API 友好的特点。

### 3.1 依赖库
```bash
npm install @dnd-kit/core @dnd-kit/sortable @dnd-kit/utilities
```

### 3.2 组件架构

#### A. ReportWorkbench (State Manager)
*   **状态管理**: 持有 `document.cells` 数组。
*   **处理函数**: `handleCellReorder(activeIndex, overIndex)`
    *   使用 `@dnd-kit/sortable` 提供的 `arrayMove` 函数更新数组顺序。

#### B. ReportNotebook (DnD Context)
*   **Context**: 引入 `DndContext` (Core) 和 `SortableContext` (Sortable)。
*   **Sensors**: 配置 `PointerSensor` (鼠标/触控) 和 `KeyboardSensor` (键盘辅助)。
*   **渲染逻辑**: 遍历 `cells`，渲染 `SortableReportCell`。

#### C. SortableReportCell (Wrapper)
*   **作用**: 包装现有的 `ReportCellReadOnly`。
*   **Hook**: `useSortable({ id: cell.id })`。
*   **Drag Handle**: 
    *   仅在 `mode === 'notebook'` 时显示。
    *   使用 `style={{ transform, transition }}` 应用位移样式。
    *   渲染一个抓手图标 (如 `GripVertical`) 作为拖拽触发区。

### 3.3 数据流图

```mermaid
graph TD
    User[用户拖拽] -->|onDragEnd| DndContext
    DndContext -->|Handle Reorder| Workbench
    Workbench -->|Update State| CellsArray
    CellsArray -->|Re-render| Notebook
    CellsArray -->|Re-render (Sync)| PreviewMode
```

## 4. 验证计划 (Verification)
1.  **基本拖拽**: 在 Notebook 模式下拖拽首个 Cell 到末尾，确认顺序交换。
2.  **模式切换**: 切换到 Preview 模式，确认顺序与 Notebook 一致。
3.  **持久化**: 刷新页面或导出报告，确认使用新顺序。
4.  **边界情况**: 测试仅有 1 个 Cell 或 0 个 Cell 时的表现。
