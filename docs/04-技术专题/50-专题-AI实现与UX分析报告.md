## 1. 核心结论

LiuliX 的 AI 实现采用了高度成熟的 **"本地优先 + 动态降级 + 严格门控"** 架构。
- **安全性**: 极其出色。三层门控 (L1/L2/L3) 和 AST 增强确保了执行安全。
- **隐私性**: 完备。统一的 `unifiedDataSanitizer` 确保敏感数据不离本地/不在此态泄露。
- **稳定性**: 健壮。Local -> Cloud 的自动降级机制保证了服务高可用。
- **体验**: 流程清晰，但仍有优化空间（如流式响应、更平滑的加载反馈）。

## 2. 架构实现分析

### 2.1 统一 AI 调用层 (`aiInvoker.ts`)
所有模块通过统一入口调用 AI，屏蔽了底层模型差异。
*   **本地优先**: 优先尝试调用 Local LLM (Ollama, Qwen 7B/14B)。
*   **智能降级**: 若本地模型未加载或超时 (30s)，自动无缝切换至云端 API (DeepSeek/Gemini)。
*   **GPU 检测**: 启动前自动检查 WebGPU 能力，决定是否推荐本地模式。

### 2.2 数据清洗模块 (`aiCleaningService.ts`)
采用 **"直出 + 强校验"** 模式。
1.  **Prompt**: 将压缩后的元数据 + 质量问题发送给 AI。
2.  **三层防御门控**:
    *   **L1 (Format)**: 校验 JSON 格式。
    *   **L2 (Static)**: SQL 注入检测 + **列名幻觉检测** (防止 AI 编造列名)。
    *   **L3 (Runtime)**: **DuckDB Dry Run**。在只读事务中预执行 SQL，获取"影响行数" (Affected Rows)。只有 Dry Run 成功的建议才会展示给用户。

### 2.3 洞察分析模块 (`useInsightLoaderV2.ts`)
采用 **"Router + Inflater" (路由 + 膨胀)** 模式，大幅降低 Token 消耗并提升稳定性。
1.  **Router**: AI 仅充当"大脑"，只返回极简的 JSON ID (如 `{"id": "trend_analysis"}`)。
    *   *优势*: 响应快，Token 少，格式错误率极低。
2.  **Inflater**: 代码中的规则引擎 (`inflater.ts`) 根据 ID "膨胀" 出完整的执行配置 (Python 代码/参数)。
3.  **Execution**: 
    *   **AST Guard**: `codeEnhancer v3.0` 对生成的 Python 代码进行 AST 静态扫描，自动修复 `df.empty` 检查，拦截危险 import。
    *   **Memory Check**: 执行前评估内存占用，决定是全量运行还是聚合运行。

## 3. 用户体验 (UX) 流程梳理

### 3.1 数据清洗 (Cleaning)
*   **触发**: 文件加载后自动触发，或用户点击 "Clean" 按钮。
*   **反馈**: `BottomPanel` 实时显示进度 ("正在脱敏...", "DuckDB 预演中...")。
*   **决策**: 
    *   用户看到的每条建议都包含了 **"预期影响"** (如 "将修改 5 行")，这是 Dry Run 的功劳，极大增强了用户信心。
    *   支持 "忽略" (Ignore) 和 "全选" 操作。
*   **闭环**: 点击 "Apply" 后，建议被应用，状态自动刷新。

### 3.2 洞察分析 (Insights)
*   **触发**: 进入页面自动加载初始洞察，或点击 "Retry"。
*   **流式感**: 
    *   虽然 API 本身非流式，但 UI 通过 `ActionChip` (推荐气泡) -> `InsightCard` (卡片) 的分步渲染，营造了渐进式体验。
*   **交互**: 
    *   **下钻 (Drill Down)**: 点击卡片上的 Chip，生成子节点。
    *   **Code Review**: 用户可展开查看 AI 生成的 Python 代码 (DuckDB -> Pandas -> Matplotlib)。
    *   **Chart**: 图表支持悬停、下载、全屏预览。

| **响应机制**   | HTTP Request/Response (全量等待)   | 长时间推理时 (如 15s+)，用户界面呈"假死"或纯 Loading 状态，焦虑感强。 | **流式响应 (SSE)**: 后端支持 Server-Sent Events，前端实时打字机效果。  | P1     |

## 6. 产品视角分析 (Product Perspective)

> 💡 **"如果我是产品经理，我会这样向用户介绍我们的 AI 流程"**

### 6.1 用户核心感受：安全感与掌控感的完美平衡

在使用 LiuliX 的过程中，用户体验的核心关键词是 **"Peace of Mind" (安心感)** 和 **"Control" (掌控感)**。

*   **安心感 (Peace of Mind)**: 
    *   不同于传统的云端 SaaS，LiuliX 将所有计算（DuckDB, Python）锁在浏览器本地。用户能直观感受到**"我的数据从未离开我的电脑"**。
    *   在清洗流程中，每一个 AI 建议都经过了 **DuckDB Dry Run** 的预演。用户看到的不是"可能是这样"，而是确凿的 **"将影响 3 行数据"**。这种确定性极大地消除了对 AI 幻觉的恐惧。
*   **掌控感 (Control)**:
    *   我们不试图用 AI 取代分析师，而是让 AI 成为最听话的**"超级实习生"**。
    *   **Router 模式** 让 AI 专注于"提思路"（生成分析类型的 ID），而执行细节（Python 代码）由我们在代码中预置的专家规则 (`inflater`) 填充。这意味着：**AI 负责灵感，规则负责质量。** 用户既享受了 AI 的发散思维，又不用担心生成的代码跑不通。

### 6.2 向用户介绍 LiuliX AI 流程话术

*"欢迎使用 LiuliX，您的私人数据科学家助手。在这里，AI 不是一个黑盒，而是一个透明、可控、永远待命的合作伙伴。"*

#### 🌟 特色一：本地优先，隐私至上 (Local-First)
> *"我们将最先进的 AI 模型搬进了您的浏览器。无论您处理的是财务报表还是客户名单，所有数据都在您的本地内存中飞速运算，连我们也无法窥视分毫。"*
> *   **背后的技术**: WebAssembly (DuckDB/Pyodide) + 本地 LLM (Ollama) + 隐私脱敏网关。

#### 🛡️ 特色二：三层防护，拒绝幻觉 (3-Layer Safety Gate)
> *"担心 AI 胡乱删改数据？LiuliX 独创了'三层防护网'。在我们向您展示任何一条建议之前，它已经通过了格式检查、安全审计和真实预演。我们只把'确定能跑通'的方案呈现在您面前。"*
> *   **背后的技术**: SQL 注入防御 + 列名幻觉检测 + Dry Run 预执行。

#### 🧠 特色三：先思考，后行动 (Router + Inflater)
> *"我们的 AI 不会盲目写代码。它会先像专家一样思考'我该做什么分析'（Router），然后调取经过验证的最佳实践代码库（Inflater）来执行。这就像让一位资深工程师审核了实习生的代码，确保每一次分析都专业、精准。"*
> *   **背后的技术**: Router Prompt 意图识别 + Inflater 规则膨胀 + AST 代码增强。
