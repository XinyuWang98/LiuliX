# 缓存项目AI预处理逻辑分析报告

## 用户问题
从IndexedDB加载缓存项目时，数据**是否会自动触发AI调用**（清洗建议、洞察建议）？

---

## 核心结论 ⚠️

### ❌ 当前**不会**自动触发AI预处理

加载缓存项目时：
- ✅ 会生成**基于规则的清洗建议**（缺失值、重复行检测）
- ❌ **不会**调用AI生成清洗建议
- ❌ **不会**调用AI生成洞察假设（除非是首次加载且无缓存）

## 关键问题

### 1. 为什么不自动调用AI？

**设计考虑**:
- 💰 **成本控制** - AI调用消耗Token，避免不必要开销
- ⏱️ **性能** - 每次加载都调用AI会很慢
- 🎯 **用户体验** - 等待AI响应可能导致卡顿

**当前策略**:
- 优先显示"快速规则建议"（即时响应）
- AI建议作为"增强功能"（用户主动触发）

### 2. 缓存假设的问题

**场景**:
```
用户之前打开过项目 → 生成了3条假设 → 退出
用户再次打开项目 → 缓存中有3条旧假设 → 不调用AI
```

**风险**:
- ⚠️ 旧假设可能**不适用于新数据**（如果数据被清洗过）
- ⚠️ 用户看到的是**过时的分析方向**

## 建议解决方案

### 方案A: 智能触发（推荐）

```typescript
// InsightChainFlow.tsx
useEffect(() => {
    const shouldRefresh = 
        hypotheses.length === 0 ||  // 无缓存
        activeFile?.analysisCache?.insight?.isStale;  // 数据已变更

    if (shouldRefresh) {
        loadHypotheses();
    }
}, [hypotheses.length, activeFile?.analysisCache?.insight?.isStale]);
```

**优点**:
- ✅ 利用已有的`isStale`机制
- ✅ 数据清洗后自动刷新假设
- ✅ 不增加不必要的AI调用

### 方案B: 后台预加载（可选）

```typescript
// 在项目加载后10秒，后台静默调用AI
setTimeout(() => {
    if (!isAILoading) {
        loadHypothesesInBackground();
    }
}, 10000);
```

**优点**:
- ✅ 用户无感知
- ✅ 提前准备好AI建议

**缺点**:
- ❌ 增加Token消耗
- ❌ 可能在用户已离开时调用

### 方案C: 用户可配置（最灵活）

```typescript
// 设置面板
const autoAISettings = {
    autoCleaningSuggestions: false,  // 自动清洗建议
    autoInsightHypotheses: true,     // 自动洞察假设
    refreshOnDataChange: true        // 数据变更时刷新
};
```
