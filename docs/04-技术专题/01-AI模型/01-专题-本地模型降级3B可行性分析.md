# 本地模型降级可行性分析 (7B → 3B)

## 1. 核心结论
**不建议直接降级。** 
在当前 **Code Interpreter (代码解释器)** 架构下，3B 模型极大概率无法满足 "直接生成可执行 Python 代码" 的智力需求，会导致洞察功能的**成功率断崖式下跌**。

**推荐策略**：保持 7B 作为主力，或仅在 "数据清洗/简单分类" 场景使用 3B，实行 **大小模型分层策略**。

---

## 2. 风险深度分析

基于目前的架构（AI 直接写代码 + 复杂 JSON 输出），降级 3B 面临三大致命风险：

### 2.1 代码生成能力的"智力阈值" (Code Generation Cap)
*   **7B 模型**：通常经过大量代码数据微调（如 Qwen2.5-7B-Coder），理解 Pandas API、Matplotlib 绘图参数的能力较强，能处理 `df.groupby().agg()` 等中等复杂度逻辑。
*   **3B 模型**：往往只具备基础的语言理解能力，**代码逻辑思维弱**。
    *   **常见故障**：幻觉不存在的函数（如 `df.plot_cool_chart()`）、忘记 import 库、变量名上下文不一致。
    *   **后果**：Skills 执行阶段报错率将从现在的 ~20% 飙升至 ~80%，导致用户频繁看到"生成失败"。

### 2.2 复杂指令遵循 (Instruction Following)
*   **现状**：我们的 Prompt (`generateBatchInsightsPrompt`) 非常长且复杂，要求：
    1.  输出特定 JSON 格式
    2.  同时按两种模式（Full/Aggregated）思考
    3.  遵守隐私规则
    4.  使用特定的列名
*   **3B 风险**：小模型的 **Attention Span (注意力跨度)** 有限，极易出现 **"指令遗忘"**。
    *   例如：写着写着忘记了要输出 JSON，变成了直接聊天。
    *   例如：忽略了 "Aggregated Mode" 的要求，只输出了 Full Mode。

### 2.3 格式稳定性 (Format Stability)
*   **现状**：系统高度依赖 AI 输出合法的 JSON 结构。
*   **3B 风险**：小模型对括号匹配 `{}`、转义字符 `\` 的控制力极差。目前的正则修复机制 (`attemptJSONRepair`) 只能修补简单的截断，无法修复结构性错乱（如嵌套层级错误）。

---

## 3. 架构适配性评估

| 任务类型 | 当前架构模式 | 3B 模型可行性 | 风险点 |
| :--- | :--- | :--- | :--- |
| **洞察生成** | **Code Interpreter** | 🔴 **极低** | 写不出能跑的 Python 代码，逻辑混乱 |
| **数据清洗** | **Function Calling** | 🟡 **中等** | 可能选对工具 `remove_duplicates`，但参数提取可能不准 |
| **报告摘要** | **Text Generation** | 🟢 **较高** | 仅做文本总结，3B 勉强够用 |
| **主题切换** | **Intent Classification** | 🟢 **高** | 简单的意图识别，3B 胜任 |

---

## 4. 如果必须降级，需要做什么？ (Mitigation Plan)

如果由于由于硬件限制（如移动端适配）必须使用 3B，必须对架构进行**降维改造**：

### 4.1 放弃 "写代码"，改为 "填参数"
*   **现状**：AI 写 `plt.plot(df['age'], df['salary'])`
*   **改造**：系统预定义好几十个绘图模板（Template），AI 只需要填槽。
    *   AI 输出：`{ "template": "scatter_plot", "x": "age", "y": "salary" }`
    *   系统侧：`dispatch_template(json)`
*   **代价**：灵活性丧失，无法生成惊艳的定制化图表，变成了"高级配置器"。

### 4.2 引入 Grammar (BNF) 约束
*   **改造**：在 WebLLM 推理时，强制开启 Grammar 约束，物理限制模型只能输出符合 Schema 的 JSON。
*   **作用**：解决格式错误问题，但解决不了逻辑错误。

### 4.3 任务拆解 (Chain of Thought)
*   **改造**：将 `batchInsightGenerator` 的大 Prompt 拆分为 3 步：
    1.  Step 1: 选列（3B 可行）
    2.  Step 2: 决定图表类型（3B 可行）
    3.  Step 3: 写代码（3B 依然不可行 -> 需转为模板匹配）

---

## 5. 结论

**Don't downgrade unless you have to.**

Code Interpreter 架构的底线就是模型的**代码逻辑能力**。目前的 7B (尤其是 Qwen2.5-7B-Instruct/Coder) 是能维持该架构运转的**最小甜点 (Sweet Spot)**。降级到 3B 将击穿体验底线。
