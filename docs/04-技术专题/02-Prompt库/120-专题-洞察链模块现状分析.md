## 3. 智能内存评估与降级机制

### 3.1 内存评估算法

```typescript
interface MemoryAssessment {
    dataPoints: number;           // 数据点总数（行×列）
    estimatedMemory: number;      // 预估内存占用（MB）
    browserMemory: number;        // 浏览器可用内存（MB）
    recommendedMode: 'full' | 'sampled' | 'aggregated';  // 推荐模式
    warningMessage?: string;      // 警告信息
}

async function assessMemoryBeforeExecution(
    tableName: string,
    selectedColumns: string[],
    analysisType: string
): Promise<MemoryAssessment> {
    const totalRows = await getTotalRows(tableName);
    const dataPoints = totalRows * selectedColumns.length;
    
    // 内存计算公式
    const dataMemory = dataPoints * 8 / 1024 / 1024;  // float64 = 8 bytes
    const pyodideOverhead = dataMemory * 2;            // pandas开销约2倍
    const estimatedMemory = dataMemory + pyodideOverhead;
    
    // 获取浏览器可用内存
    const browserMemory = (performance as any).memory?.jsHeapSizeLimit 
        ? (performance as any).memory.jsHeapSizeLimit / 1024 / 1024 
        : 2048;  // 默认2GB
    
    // 决策逻辑
    let recommendedMode: 'full' | 'sampled' | 'aggregated';
    let warningMessage: string | undefined;
    
    if (estimatedMemory < browserMemory * 0.2) {  // <20%内存
        recommendedMode = 'full';
    } else if (estimatedMemory < browserMemory * 0.5) {  // 20-50%内存
        recommendedMode = 'sampled';
        warningMessage = `数据量较大（${totalRows}行），将采用10%分层采样`;
    } else {  // >50%内存
        recommendedMode = 'aggregated';
        warningMessage = `数据量过大（${totalRows}行），降级采用DuckDB预聚合`;
    }
    
    logger.log('内存评估', '执行前检查', {
        rows: totalRows,
        columns: selectedColumns.length,
        estimatedMB: estimatedMemory.toFixed(2),
        browserMB: browserMemory.toFixed(2),
        mode: recommendedMode
    });
    
    return {
        dataPoints,
        estimatedMemory,
        browserMemory,
        recommendedMode,
        warningMessage
    };
}
```

### 3.3 内存测算与实际场景

#### **数据分析师笔记本配置基准**

**典型配置**：
- RAM: 16GB
- Chrome浏览器可用内存: ~4GB（单标签页限制）
- 实际可用: 4096MB

#### **计算公式**
```typescript
estimatedMemory = dataPoints × 8 bytes × 3（pandas开销）
                = dataPoints × 24 bytes
```

#### **三种执行模式的临界点**

| 执行模式 | 内存占用 | 可用内存 | 最大数据点 | 常见场景（行×列） |
|---------|---------|---------|-----------|----------------|
| **full** | <20% | 819MB | **35,791,394点** | **50万行×70列**<br/>100万行×35列<br/>10万行×350列 |
| **sampled** | 20-50% | 2048MB | **89,478,486点** | **200万行×45列**<br/>100万行×89列<br/>10万行×890列 |
| **aggregated** | >50% | >2048MB | **>89,478,486点** | **500万行×18列**<br/>100万行×894列 |

#### **实际业务场景测算**

**场景1：典型用户数据分析（50万行×20列）**
```
数据点 = 500,000 × 20 = 10,000,000
内存占用 = 10M × 24 bytes = 240MB
内存占比 = 240MB / 4096MB = 5.8%
执行模式 = ✅ full（全量，无压力）
```

**场景2：电商订单分析（100万行×50列）**
```
数据点 = 1,000,000 × 50 = 50,000,000
内存占用 = 50M × 24 bytes = 1200MB
内存占比 = 1200MB / 4096MB = 29.3%
执行模式 = ⚠️ sampled（10%采样）
```

**场景3：大规模日志分析（500万行×30列）**
```
数据点 = 5,000,000 × 30 = 150,000,000
内存占用 = 150M × 24 bytes = 3600MB
内存占比 = 3600MB / 4096MB = 87.9%
执行模式 = 🔴 aggregated（DuckDB预聚合）
```

#### **不同列数下的行数上限**

| 列数 | full模式上限 | sampled模式上限 | 说明 |
|------|-------------|----------------|------|
| **10列** | 3,579,139行 | 8,947,849行 | 典型小数据集 |
| **20列** | 1,789,570行 | 4,473,924行 | 常见业务数据 |
| **50列** | 715,828行 | 1,789,570行 | 宽表分析 |
| **100列** | 357,914行 | 894,785行 | 超宽表 |
| **200列** | 178,957行 | 447,392行 | 特征工程 |

#### **关键发现**

**数据分析师的"安全区"（full模式）**：
- **50万行 × 70列** = 35M数据点（最大无降级场景）
- **100万行 × 35列** = 35M数据点
- **10万行 × 350列** = 35M数据点

> [!IMPORTANT]
> 对于**百万行以内、百列以内**的数据集，数据分析师笔记本可以**全量无损**分析，覆盖90%以上的日常场景。

#### **不同硬件配置对比**

| 配置 | RAM | 浏览器可用 | full上限（行×列） | 推荐使用场景 |
|------|-----|----------|----------------|-------------|
| **入门** | 8GB | 2GB | 25万行×70列 | 个人学习、小数据集 |
| **标准** | 16GB | 4GB | 50万行×70列 | 数据分析师主力机 |
| **高配** | 32GB | 8GB | 100万行×70列 | 数据科学家、大数据分析 |

#### **实用建议**

1. **≤50万行** → 直接全量分析，无需担心
2. **50万-200万行** → 使用分层采样（10%）
3. **>200万行** → 依赖DuckDB预聚合

        'import numpy as np',
        'import base64',
        'from io import BytesIO',
        'import json'

function convertSQLToPandas(sqlQuery: string): string {
    // 解析SQL（简化示例）
    const parsed = parseSQL(sqlQuery);
    
    if (parsed.groupBy && parsed.aggregations) {
        // GROUP BY + COUNT 模式
        return `
# 步骤1：加载原始数据
df_raw = pd.read_csv('${parsed.tableName}.csv')

# 步骤2：Python聚合（等效于SQL）
${generateGroupByCode(parsed)}

# 步骤3：排序
df = df.sort_values('${parsed.groupByColumn}')
`;
    }
    
    // 其他SQL模式...
}

function generateGroupByCode(parsed: SQLParsed): string {
    if (parsed.aggregations.includes('COUNT(*)')) {
        return `
# 使用整除实现分箱（等效SQL中的CAST(${parsed.column}/5 AS INT)*5）
df_raw['${parsed.groupByColumn}'] = (df_raw['${parsed.column}'] // ${parsed.binSize}) * ${parsed.binSize}

# 聚合计数
df = df_raw.groupby('${parsed.groupByColumn}').size().reset_index(name='count')
`;
    }
    
    // 其他聚合函数...
}

## 5. Prompt库集成方案（未来规划）

### 5.1 核心价值

**当前状态**：硬编码Prompt → AI生成 → Pyodide执行  
**目标状态**：Prompt库模板 → 变量注入 → AI调用Skills → 质量验证

**关键创新**：Prompt库不是"直接给AI答案"，而是"告诉AI应该怎么思考、用什么工具、输出什么格式"。

### 5.2 集成架构（三层保障）

```typescript
// Layer 1: Prompt模板定义
interface PromptTemplate {
    id: 'ecommerce-rfm-analysis',
    title: 'RFM用户分层分析',
    
    // 前置条件检查
    prerequisite: {
        requiredColumns: ['user_id', 'order_date', 'amount'],
        minRows: 1000
    },
    
    // Prompt模板（支持变量）
    template: `基于RFM方法分析用户...
        用户ID列：{{USER_ID_COLUMN}}
        订单日期列：{{ORDER_DATE_COLUMN}}
        ...`,
    
    // 指定执行工具
    allowedSkills: ['sys_run_python', 'viz_create_chart'],
    
    // 输出验证规则
    outputValidation: {
        mustContain: ['RFM值', '用户分层'],
        confidenceThreshold: 60
    }
}

// Layer 2: 智能匹配与注入
async function applyPromptTemplate(promptId, currentData) {
    const template = promptLib.getById(promptId);
    
    // 验证前置条件
    validatePrerequisites(template.prerequisite, currentData);
    
    // 自动匹配列名
    const columnMapping = {
        USER_ID_COLUMN: findColumn(['user_id', 'customer_id']),
        ORDER_DATE_COLUMN: findColumn(['order_date', 'date'])
    };
    
    // 注入统计信息
    const stats = {
        UNIQUE_USERS: await runQuery('SELECT COUNT(DISTINCT user_id)'),
        AVG_AMOUNT: metadata.stats_numeric.median
    };
    
    // 生成最终Prompt
    return injectVariables(template.template, {...columnMapping, ...stats});
}

// Layer 3: 输出验证
function validateAIOutput(aiResponse, validationRules) {
    // 检查Skills调用
    if (!aiResponse.tool_calls) throw new Error('AI未调用工具');
    
    // 验证输出内容
    const missingKeywords = validationRules.mustContain.filter(
        kw => !finalText.includes(kw)
    );
    
    if (missingKeywords.length > 0) {
        return { status: 'review_required', reason: `缺少${missingKeywords}` };
    }
    
    return { status: 'valid' };
}
```

### 5.3 Prompt库分类体系

**多维分类**（支持交叉筛选）：

| 维度 | 分类 | 示例 |
|------|------|------|
| **分析意图** | 探索/诊断/预测/优化/报告 | 🔍探索性、🩺诊断性 |
| **技术方法** | 描述性/因果推断/用户分析/时间序列/A/B测试 | RFM、DID、Cohort分析 |
| **行业领域** | 电商/金融/SaaS/医疗/通用 | 电商用户分层、金融风控 |
| **技能水平** | 初学者/进阶/专家 | 🌱一键生成、🎓因果推断 |

### 5.4 质量门控机制

**先执行验证，后展示**：置信度<60%的洞察不展示给用户

```typescript
interface QualityGate {
    codeExecutable: boolean;        // 代码是否成功执行
    hasValidOutput: boolean;        // 是否有图表/表格输出
    confidenceScore: number;        // 综合评分 0-100
    confidenceThreshold: number;    // 用户可调阈值（默认60）
    dataQualityIssues: string[];    // 数据质量问题
}

// 置信度计算公式
score = 代码质量(30分) + AI自信度(40分) + 数据覆盖率(20分) + 统计显著性(10分)
```
