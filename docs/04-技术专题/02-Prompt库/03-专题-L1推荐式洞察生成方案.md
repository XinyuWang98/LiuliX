# L1 推荐式洞察生成方案 (Router-Based Insight Generation)

## 1. 核心理念

将洞察生成从 **"Generative (生成式)"** 模态转变为 **"Retrieval-Augmented (检索增强)"** 模态。

*   **现状 (Lv1 Coder)**: AI 像一个应届毕业生，每次都要手写每一行代码。
    *   缺点：慢、容易错、Token 消耗巨大。
*   **目标 (Lv3 Editor)**: AI 像一个资深主编，只负责选题（Insight Type）和指派（Columns），代码由系统内置的"资深工兵"（Templates）自动填充。

---

## 2. 架构设计

### 2.1 模板注册表 (The Registry)
创建一个强类型的模板库，定义所有支持的分析方法。

```typescript
// src/services/insights/registry.ts

export const INSIGHT_TEMPLATES = {
  'distribution_1d': {
    name: '单变量分布',
    description: '展示数值型变量的直方图分布',
    required_cols: ['target'],
    full_mode_template: `df['{{target}}'].plot(kind='hist')...`,
    aggregated_mode_template: `SELECT histogram({{target}})...`
  },
  'correlation_2d': {
    name: '相关性分析',
    required_cols: ['x', 'y'],
    // ...
  },
  'trend_time': {
    name: '趋势分析',
    required_cols: ['date_col', 'value_col'],
    // ...
  }
}
```

### 2.2 极简 Prompt 设计 (The Router Prompt)
重构 `batchInsightGenerator`，不再要求 AI 写代码，只要求它返回 **轻量级 JSON**。

**Prompt 示例**:
> "请从 ['distribution_1d', 'correlation_2d', 'trend_time'] 中选择最适合当前数据的 3 个分析角度。
> 返回格式：
> ```json
> [
>   { "type": "distribution_1d", "args": { "target": "price" }, "title": "价格分布" },
>   { "type": "trend_time", "args": { "date_col": "date", "value_col": "sales" }, "title": "销量趋势" }
> ]
> ```

### 2.3 膨胀引擎 (The Inflater)
在系统侧（TypeScript）实现一个 "膨胀器"，将 AI 的轻量级 JSON 还原为完整的 `InsightSuggestion` 对象。

```typescript
function inflateInsights(miniInsights: MiniInsight[]): InsightSuggestion[] {
  return miniInsights.map(mini => {
    const template = INSIGHT_TEMPLATES[mini.type];
    // 1. 注入 Full Mode 代码
    const fullCode = render(template.full_mode_template, mini.args);
    // 2. 注入 Aggregated Mode SQL
    const aggSql = render(template.aggregated_mode_template, mini.args);
    
    return {
      title: mini.title,
      full_mode: { code: fullCode },
      aggregated_mode: { sql: aggSql, viz_code: ... }
    };
  });
}
```

## 3. 实施步骤

### Step 1: 模板提取 (Refactoring)
*   分析现有 `fallbackTemplates.ts` 和 `batchInsightGenerator.ts` 中的 Prompt。
*   将硬编码的 Python/SQL 逻辑抽离出来，整理成 `src/services/insights/templates/` 目录下的独立文件。

### Step 2: Prompt 降维 (Prompt Engineering)
*   修改 `generateBatchInsightsPrompt`。
*   移除所有关于 "Python语法"、"Matplotlib绘图规范" 的冗长指令（这些约束现在由模板保证）。
*   新增 "可用模板列表" 的描述。

### Step 3: 引擎对接 (Integration)
*   修改 `useInsightLoaderV2.ts`。
*   在 `parseBatchInsightsResponse` 后增加 `inflateInsights` 调用。

---

## 4. 收益预估

| 指标 | 优化前 (Coder模式) | 优化后 (Router模式) | 提升幅度 |
| :--- | :--- | :--- | :--- |
| **Output Tokens** | ~1500 tokens | ~150 tokens | **10x** |
| **3B 模型可用性** | ❌ 不可用 | ✅ 完美支持 | **Qualitative** |
| **代码错误率** | ~20% (幻觉/语法错误) | **0%** (模板保证) | **Qualitative** |
| **响应耗时** | ~15s (本地7B) | ~2s (本地7B) | **7x** |

## 5. 结论

这是实现 **"本地优先 (Local-First)"** 战略的关键一步。它不仅让 3B 模型成为可能，更让 7B 模型的体验从 "能用" 变为 "秒出"。
