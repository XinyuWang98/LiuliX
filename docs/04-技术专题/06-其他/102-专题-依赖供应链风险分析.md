# 专题：依赖供应链与离线化风险分析

> [!WARNING]
> 本文档分析 DataPrism 对外部网络环境的依赖风险，重点评估 WASM 组件（Pyodide/DuckDB）在离线或内网环境下的可用性。

## 1. 概述 (Executive Summary)

DataPrism 定位为"本地优先"的数据分析工具，但目前的工程实现中，核心计算引擎（Pyodide）存在**强外部 CDN 依赖**。这意味着在无外网环境（如企业内网、飞机上）或 CDN 故障时，**核心数据分析功能将完全瘫痪**。这是一个 P0 级别的供应链安全风险。

## 2. 依赖现状深度审计

### 2.1 🔴 Pyodide (Python Engine) - [高危]
*   **加载方式**: 动态加载，硬编码 CDN URL。
*   **代码位置**: `src/workers/pyodide/worker.ts`
    ```typescript
    pyodide = await loadPyodide({
        indexURL: "https://cdn.jsdelivr.net/pyodide/v0.26.4/full/"
    });
    ```
*   **扩展包**: Pandas, Numpy, Matplotlib 也是通过 `await pyodide.loadPackage(...)` 从上述 indexURL 动态下载 whl 文件。
*   **风险**:
    1.  **断网不可用**: 无法初始化 Python 环境。
    2.  **CDN 劫持风险**: 理论上 CDN 内容被篡改可能导致恶意代码执行（WASM 沙箱内）。
    3.  **内网穿透**: 企业防火墙常屏蔽 `jsdelivr.net`。

### 2.2 🟡 DuckDB-WASM (SQL Engine) - [中风险]
*   **加载方式**: 通过 Vite 的 URL Import 机制打包。
*   **代码位置**: `src/db/duckdbEngine.ts`
    ```typescript
    import duckdb_mvp from '@duckdb/duckdb-wasm/dist/duckdb-mvp.wasm?url';
    ```
*   **现状**: Vite 会在构建时将 `.wasm` 文件作为静态资源哈希化并放入 `dist/assets`。
*   **优势**: 只要 web 服务器（或本地文件服务器）能访问，DuckDB 就能运行。已实现**基本离线化**。
*   **风险**: 需确认 `dist` 产物中是否真的包含了完整的 wasm/worker 文件，且路径解析正确。

### 2.3 🟢 NPM 静态依赖 (React/UI) - [低风险]
*   所有 UI 库（React, Chart.js, Lucide）均打包在 `index-[hash].js` 中，无运行时外部依赖。

## 3. 风险评估矩阵

| 组件 | 依赖类型 | 离线可用性 | 风险等级 | 潜在后果 |
| :--- | :--- | :--- | :--- | :--- |
| **App Shell** | Static Bundle | ✅ Yes | Low | 只有 UI，无功能 |
| **SQL Engine** | Local Asset | ✅ Yes | Low | 正常运行 |
| **AI Engine** | API Call | ❌ No | High | 需外网 (Mock 可兜底) |
| **Python Engine** | **External CDN** | **❌ No** | **Critical** | **分析功能全挂** |

## 4. 离线化改造方案 (Mitigation Plan)

为了实现"真·本地可用"，必须对 Pyodide 进行私有化部署改造。

### 4.1 方案 A：Self-Hosting Pyodide (推荐)
1.  **下载内核**: 下载 Pyodide v0.26.4 完整包（包含 core, pandas, numpy, matplotlib 等 whl）。
2.  **静态托管**: 将这些文件放入 `public/pyodide/` 目录。
3.  **修改加载逻辑**:
    ```typescript
    // src/workers/pyodide/worker.ts
    // 自动检测环境，开发环境用 CDN，生产环境用本地
    const indexURL = import.meta.env.PROD 
        ? '/pyodide/' 
        : "https://cdn.jsdelivr.net/pyodide/v0.26.4/full/";
    
    pyodide = await loadPyodide({ indexURL });
    ```
4.  **构建影响**: 会显著增加最终构建产物体积（约 30MB-50MB），建议配合 HTTP 缓存策略。

### 4.2 方案 B：Service Worker 缓存
*   利用 PWA 机制，在用户第一次访问（有网）时由 Service Worker 拦截并缓存 CDN 资源。
*   **缺点**: 首次使用必须联网，无法解决纯内网部署问题。

## 5. 结论与行动

当前架构存在**"伪本地"**风险。虽然数据不上传，但代码运行依赖公网。

**建议立即执行**:
1.  [ ] **下载 Pyodide 离线包**并集成到项目中 (方案 A)。
2.  [ ] **配置 Vite** 确保大文件 WASM 正确处理 MIME Type。
3.  [ ] **添加构建检查**: 在 CI/CD 中通过 `grep` 检查构建产物是否包含硬编码的外部 URL。

这对企业级交付是**绝对必要**的前置条件。
