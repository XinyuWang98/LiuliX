# 专题：洞察链 (Insight Chain) 模块现状分析

**作者**: Google Antigravity Agent
**日期**: 2025-12-21
**版本**: v1.0

## 1. 模块概述

洞察链 (Insight Chain) 是 DataPrism 的核心智能分析模块，旨在通过“假设驱动分析” (Hypothesis-Driven Analysis) 的方式，引导用户从宏观假设逐步深入到具体的数据洞察。

**核心流程**:
1.  **假设生成**: 基于数据摘要（列名、行数、采样数据）自动生成 3 条初始分析假设。
2.  **深度挖掘**: 用户点击假设后，系统生成初始的可视化洞察节点。
3.  **追问深挖**: 用户可以针对特定假设进行自然语言追问 (Deep Dive)，生成新的子洞察节点，形成分析链条。
4.  **证据采纳**: 用户认可分析结果后，可将整条洞察链作为“证据”采纳，存入证据池。

## 3. 问题与风险

### 3.1 高度依赖 Mock 数据 (High Risk)
代码中存在大量的 Mock 数据回退逻辑（如 `hyp-mock-0`, `hyp-mock-1`）。
*   **风险**: 一旦 AI 服务不稳定或 Key 失效，用户将看到与实际数据完全无关的 Mock 结论（如 "年龄与薪资正相关"），这在生产环境中是不可接受的误导。
*   **位置**: `InsightChainFlow.tsx` lines 145-173 (假设生成失败回退), lines 237-252 (洞察生成失败回退)。

### 3.2 数据采样局限性
*   **现状**: `loadHypotheses` 仅采样前 1000 行 (`sampleDataForAI`) 发送给 AI。
*   **风险**: 对于非均匀分布的数据，前 1000 行可能无法代表整体特征，导致生成的假设有偏差。

### 3.3 可视化类型推断脆弱
*   **现状**: 依赖简单的关键词匹配 (`CHART_TYPE_KEYWORDS`) 或 AI 返回的 `chartType` 字符串。
*   **风险**: 如果 AI 返回的 `chartType` 不在预定义列表中（如 'pie', 'heatmap'），前端将降级为表格或报错。

## 4. 优化建议

### 4.1 移除误导性 Mock 数据 (Priority: High)
*   **建议**: 在生产环境或非演示模式下，**彻底移除** 业务逻辑中的 Mock 数据兜底。
*   **替代方案**: AI 调用失败时，应明确展示错误提示（如 "AI 服务暂时不可用"），并提供“重试”按钮，而不是展示虚假的 Mock 分析结果。

### 4.2 增强数据采样策略 (Priority: Medium)
*   **建议**: 实现更智能的采样策略，例如分层采样或随机采样（不仅仅是 `LIMIT 1000`），或者在后端/DuckDB 层计算统计特征（Min/Max/Mean/NullCount）发送给 AI，而非原始行数据。

### 4.3 完善图表渲染与代码执行 (Priority: High)
*   **建议**:
    1.  **沙箱执行**: 前端目前仅展示代码 (`node.code`)，并未实际在浏览器中执行 Python 代码生成图表。这是一个巨大的“断层”。
    2.  **WebPy/Pyodide 集成**: 考虑引入 Pyodide 在浏览器端实际运行 AI 生成的 Python 代码，或者将代码发送回后端执行，以确保图表与数据真实对应。目前看来图表数据 (`chartData`) 也是 AI "瞎编" (Hallucinated) 出来的，而非代码运行结果。**这是最大的逻辑漏洞。**

### 4.4 增强上下文关联
*   **建议**: 在深挖追问时，Prompt 应包含上一轮的洞察结论，以支持多轮对话的上下文连贯性。目前的 Prompt 似乎每次都是独立的。

## 5. 结论

洞察链模块在架构设计上是合理的，交互流程也已跑通。但目前最大的问题在于**“分析结果的真实性”**。目前 AI 既生成代码又生成（编造）图表数据，二者可能不一致。

**下一步核心任务**: 实现代码的**真实执行**（通过 WebWorker/Pyodide 或 后端 Kernel），让图表基于真实数据渲染，而非依赖 AI 的幻觉生成。
