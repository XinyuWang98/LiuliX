# 分析报告界面布局优化方案 (Analysis Report UI Optimization)

## 1. 现状分析 (Current State)

目前 `ContentPanel -> ReportGenerator` 采用垂直堆叠布局，组件层级如下：

```
[垂直流式布局 Vertical Stack]
+--------------------------------------------------+
| ContentPanel (Main Container)                    |
|                                                  |
| ... (Project / Cleaning / Insights Sections) ... |
|                                                  |
| +----------------------------------------------+ |
| | Section Header: Analysis Report              | |
| | [Title] [Evidence Badge]                     | |
| +----------------------------------------------+ |
|                                                  |
| +----------------------------------------------+ |
| | ReportGenerator (Container)                  | |
| |                                              | |
| |  [1] EvidencePoolHorizontal                  | |
| |  +----------------------------------------+  | |
| |  | [Title] [Count]                        |  | |
| |  | [Card] [Card] [Card] (Scrollable)      |  | |
| |  +----------------------------------------+  | |
| |                                              | |
| |  [2] Toggle Button (Hide/Show Notebook)      | |
| |      [v] Expand/Collapse                     | |
| |                                              | |
| |  [3] ReportNotebook (Conditional)            | |
| |  +----------------------------------------+  | |
| |  | [Header: Title, Mode, Exports]         |  | |
| |  | [Progress Bar]                         |  | |
| |  | [Cell List Vertical]                   |  | |
| |  +----------------------------------------+  | |
| +----------------------------------------------+ |
+--------------------------------------------------+
```

### 存在的问题
1.  **垂直空间割裂**：证据池（Evidence Pool）始终占据顶部空间，即使用户专注于写作，也需要手动滚动。
2.  **操作分散**：
    *   报告主操作（导出、签字）位于 `ReportNotebook` 内部。
    *   证据管理位于 `EvidencePool` 内部。
    *   两者缺乏统一的“工作台”视感。
3.  **视觉层级冗余**：存在多层嵌套的边框和背景（Section -> Generator -> Notebook），导致界面显得不够轻量。

---

## 2. 优化方案 (Proposed Optimization)

**核心理念**：打造“沉浸式写作工作台” (Immersive Writer's Workbench)。将证据池作为“工具箱”，报告编辑区作为“主画布”，通过一体化容器整合。

### 优化后布局 (ASCII Diagram)

```
[一体化玻璃拟态容器 Unified LiuliGlass Container]
+---------------------------------------------------------------+
|  [Header & Toolbar Area (Sticky)]                             |
|  +---------------------------------------------------------+  |
|  | 📄 Report Title (Editable)      [View Mode: Edit/View]  |  |
|  | Status: Draft (3/5 Approved)    [Export] [Sign Report]  |  |
|  +---------------------------------------------------------+  |
|                                                               |
|  [Reference Tray (Evidence Pool) - Collapsible]               |
|  +---------------------------------------------------------+  |
|  | [v] Evidence Reference (5 Items) [Pin All] [Clear]      |  |
|  | +-----------------------------------------------------+ |  |
|  | | [Small Card] [Small Card] [Small Card] ...          | |  |
|  | +-----------------------------------------------------+ |  |
|  +---------------------------------------------------------+  |
|                                                               |
|  [Main Editor Area]                                           |
|  +---------------------------------------------------------+  |
|  |                                                         |  |
|  |  +---------------------------------------------------+  |  |
|  |  | Cell 1: Business Insight (InsightChain Node)      |  |  |
|  |  | [Chart Preview]                                   |  |  |
|  |  | [Text Editor Area]                                |  |  |
|  |  +---------------------------------------------------+  |  |
|  |                                                         |  |
|  |  +---------------------------------------------------+  |  |
|  |  | Cell 2: Cleaning Log                              |  |  |
|  |  | ...                                               |  |  |
|  |  +---------------------------------------------------+  |  |
|  |                                                         |  |
|  +---------------------------------------------------------+  |
|                                                               |
+---------------------------------------------------------------+
```

### 关键改进点

1.  **一体化容器 (Unified Container)**
    *   **现状**：`EvidencePool` 和 `ReportNotebook` 是两个分离的积木。
    *   **优化**：移除中间的间隙，使用一个大的 `<LiuliGlass>` 包裹整个区域。顶部统一为 Toolbar，不再有重复的 Section Title。

2.  **置顶工具栏 (Sticky Header)**
    *   将 `ReportNotebook` 中的**导出（Export）、签字（Sign）、模式切换（View Mode）** 上浮到最顶层。
    *   无论滚动到哪里，操作按钮始终可见。

3.  **可折叠证据托盘 (Collapsible Reference Tray)**
    *   **现状**：`EvidencePoolHorizontal` 占据固定高度。
    *   **优化**：将其改为“托盘（Tray）”模式。
        *   **展开态**：显示卡片流，可拖拽或点击插入。
        *   **收起态**：仅显示一行“引用素材 (5)”，点击展开。
    *   视觉上使用更深色的背景（`var(--bg-secondary)`）区分于写作区，通过阴影区分层级。

4.  **无缝编辑器 (Seamless Editor)**
    *   移除 `ReportNotebook` 自身的额外 Padding 和 Title，使其直接衔接在工具栏下方。
    *   Cell 之间的间距（Gap）稍微增大，增加呼吸感。

## 3. 样式变量建议 (CSS Variables)

为符合 LiuliX 设计系统，建议使用以下变量重构：

*   **容器背景**：`var(--glass-surface)` (保持一致的磨砂感)
*   **托盘背景**：`rgba(0, 0, 0, 0.03)` (轻微深色，区分功能区)
*   **工具栏背景**：`var(--bg-main)` + `backdrop-filter: blur(20px)`
*   **分割线**：`var(--glass-border)`
*   **字体**：
    *   标题：`var(--fs-xl)` + `var(--fw-bold)`
    *   正文：`var(--fs-base)` (确保阅读体验)

## 4. 后续行动建议

1.  **组件拆分**：将 `ReportGenerator` 重构为 `ReportWorkbench`。
2.  **状态提升**：将 `ReportNotebook` 的内部状态（如 signedStatus）提升到 `ReportWorkbench` 统一管理。
3.  **交互增强**：利用 React Context 实现证据卡片点击后自动滚动到对应的 Report Cell（如果已关联）。

## 5. 补充：Notebook 切换按钮位置优化 (2026-01-05)

### 变更背景
此前 Notebook 的切换按钮直接位于 `LiveNotebookPanel` 内部。这导致了一个严重的交互逻辑缺陷：当用户点击“收起”后，整个面板（包含按钮本身）都会从 DOM 中移除或隐藏，导致用户无法再找到“展开”按钮，形成了不可逆操作。

### 优化方案
将切换按钮上移至外层的 `section-header`（洞察分析区域的标题栏）。

#### 布局调整：
- **容器**：`ContentPanel.tsx` 中的 `.section-header`。
- **对齐**：使用 `justify-content: space-between` 确保标题在左，按钮在右。
- **样式**：采用 `.notebook-toggle-btn` 类，集成 LiuliX 玻璃态样式。

#### 交互逻辑：
- **状态持久化**：使用 `localStorage.setItem('insightFlow.showNotebook', ...)` 记忆用户习惯。
- **始终可见**：由于按钮位于 `section-header` 级别，它不隶属于 Notebook 面板，因此在面板收起后依然保留，解决了“不可逆性”问题。

#### 结构图示：
```
+-------------------------------------------------------+
| section-header                                        |
| [标题: 洞察分析]                  [按钮: 收起/展开 Notebook] |
+-------------------------------------------------------+
| content-module-container                              |
| +-------------------------+ +-----------------------+ |
| | InsightChainFlow (Main) | | LiveNotebook (Side)    | |
| +-------------------------+ +-----------------------+ |
+-------------------------------------------------------+
```

此优化提升了 UI 的直观性，并确保了功能的完整闭环。
