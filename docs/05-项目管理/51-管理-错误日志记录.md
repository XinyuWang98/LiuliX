}, [

# 2025-12-18 重构导致数据加载失败

## 场景
DataViewer.tsx 重构后，数据表显示元数据而非实际数据

## 问题描述
错误流程：
1. 尝试使用旧 tableName (t_1765702707436_working) -> 表不存在
2. 准备重新 ingest -> 调用 DataLoadingService.loadWithDuckDB
3. **无法获取原始文件对象** -> DuckDB 失败
4. 回退到 Pyodide -> 也失败
5. 最终显示文件元数据

## 原因分析
重构时删除了关键回退逻辑：
- 原代码：检查 ile.data.originalFile -> 检查 ile.data.rawFile -> **从 file.data.data (JSON) 重建 CSV**
- 新代码：只检查 ile.data.rawFile || file.data.file -> 直接抛出错误

旧文件的 rawFile 对象已丢失（浏览器刷新后 File 对象无法持久化），必须从 JSON 数据重建！

## 解决方案
在 dataLoadingService.ts 的 loadWithDuckDB 中添加 CSV 重建逻辑：
```typescript
// 优先使用原始文件
const rawFile = file.data.rawFile || file.data.originalFile || file.data.file;

if (!rawFile) {
    // 回退：从 JSON 数据重建 CSV
    const data = file.data.data;
    if (!data || data.length === 0) {
        throw new Error('无法获取原始文件对象且无数据可重建');
    }
    
    const headers = Object.keys(data[0]);
    let csvContent = headers.join(',') + '\\n';
    data.forEach((row: any) => {
        csvContent += headers.map(h => {
            const val = row[h];
            return val === null || val === undefined ? '' : String(val);
        }).join(',') + '\\n';
    });
    
    const blob = new Blob([csvContent], { type: 'text/csv' });
    const csvFile = new File([blob], file.data.fileName, { type: 'text/csv' });
    return await engine.ingestCSV(csvFile, options);
}
```

#逻辑重构 #回退机制缺失

# 2026-01-01 端到端测试报错分析 (已解决)

## 场景
启动后端服务后进行端到端测试，控制台涌现各类报错。

## 问题描述
1. **i18n 缺失**: `Translation key not found: analysis.initializing`, `progress.sendingRequest`, `progress.generatingInsight`
2. **DuckDB 语法错误**: `Parser Error: syntax error at end of input` (在 Skills full_mode 执行期间)
3. **类型错误**: `TypeError: Cannot create property 'analysisCache' on string 'housing.csv'`

## 原因分析
1. **i18n**: `src/locales/*/analysis.ts` 中 `analysis` 对象缺少 `initializing` 键；`progress` 命名空间完全缺失。
2. **Type Error**: `CacheManager.updateInsightTimestamp` 期望接收 `ProjectFile` 对象，但调用方 (`useInsightLoaderV2.ts`) 错误地传入了 `fileName` 字符串。
3. **DuckDB Error**: AI 生成的代码可能包含不完整的 SQL，或者 Python 执行环境与 DuckDB 交互时 SQL 截断。即使代码长度正常 (2000+ chars)，仍报语法错误，需检查 SQL 生成逻辑。

## 解决方案 (已执行)
1. **i18n**: 在 `src/locales/zh-CN/analysis.ts` 和 `src/locales/en-US/index.ts` 中补全了缺失的键值，并更新了 `src/types/i18n.ts` 类型定义。
2. **Type Error**: 修正了 `InsightChainFlow.tsx` 以接收 `file` 对象，并更新 `useInsightLoaderV2.ts` 签名以接受 `ProjectFile`。
3. **DuckDB**: 在 `modeExecutor.ts` 中添加了 `tableName` 检查，并优化了数据加载流程。

## 验证结果
- 浏览器端验证通过，页面加载正常，初始化无报错。
- `npm run type-check` 通过。
