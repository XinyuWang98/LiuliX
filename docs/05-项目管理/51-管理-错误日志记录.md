# 2025-12-18 重构导致数据加载失败

## 场景
DataViewer.tsx 重构后，数据表显示元数据而非实际数据

## 问题描述
错误流程：
1. 尝试使用旧 tableName (t_1765702707436_working) -> 表不存在
2. 准备重新 ingest -> 调用 DataLoadingService.loadWithDuckDB
3. **无法获取原始文件对象** -> DuckDB 失败
4. 回退到 Pyodide -> 也失败
5. 最终显示文件元数据

## 原因分析
重构时删除了关键回退逻辑：
- 原代码：检查 ile.data.originalFile -> 检查 ile.data.rawFile -> **从 file.data.data (JSON) 重建 CSV**
- 新代码：只检查 ile.data.rawFile || file.data.file -> 直接抛出错误

旧文件的 rawFile 对象已丢失（浏览器刷新后 File 对象无法持久化），必须从 JSON 数据重建！

## 解决方案
在 dataLoadingService.ts 的 loadWithDuckDB 中添加 CSV 重建逻辑：
```typescript
// 优先使用原始文件
const rawFile = file.data.rawFile || file.data.originalFile || file.data.file;

if (!rawFile) {
    // 回退：从 JSON 数据重建 CSV
    const data = file.data.data;
    if (!data || data.length === 0) {
        throw new Error('无法获取原始文件对象且无数据可重建');
    }
    
    const headers = Object.keys(data[0]);
    let csvContent = headers.join(',') + '\\n';
    data.forEach((row: any) => {
        csvContent += headers.map(h => {
            const val = row[h];
            return val === null || val === undefined ? '' : String(val);
        }).join(',') + '\\n';
    });
    
    const blob = new Blob([csvContent], { type: 'text/csv' });
    const csvFile = new File([blob], file.data.fileName, { type: 'text/csv' });
    return await engine.ingestCSV(csvFile, options);
}
```

# 2026-01-05 F-19: 图片加载 431 错误修复

## 场景
在洞察下钻流程中，部分 Base64 图表图片无法加载，报 431 (Request Header Fields Too Large) 错误。

## 问题描述
1. 页面显示“图片加载失败”。
2. 控制台网络请求返回 431 状态码。
3. Base64 字符串过长（通常超过几万字符），直接作为 `img src` 或在某些组件传递过程中超出了 HTTP 头或 URL 限制。

## 原因分析
1. **长度溢出**: 原生 Base64 字符串直接作为 URL 传递时非常笨重。
2. **逻辑缺陷**: `ChartImage.tsx` 原逻辑仅处理带 `data:image` 前缀的字符串。部分后台返回的图片是 raw Base64，被误认为普通 URL 进行加载，导致浏览器尝试发起非法 HTTP 请求。

## 解决方案
1. **Blob URL 转换**: 引入 `base64ToBlobUrl` 工具，将 Base64 转换为匿名的 `blob:` 协议引用。
2. **格式化增强**: 在 `ChartImage.tsx` 中增加逻辑，自动识别并补全 raw Base64 的 Data URI 前缀，确保转换成功。
3. **内存管理**: 在 `useEffect` 的 cleanup 函数中调用 `URL.revokeObjectURL` 释放内存。

## 策略标签
#图片加载修复 #Base64转Blob #F19 #性能优化

# 2026-01-10 ProjectCard 事件对象方法缺失报错 (已解决)

## 场景
用户点击项目卡片的"更多操作"按钮（三点图标），弹出右键菜单。

## 问题描述
浏览器控制台报错：
```
Uncaught TypeError: e.preventDefault is not a function
    at handleContextMenu (ProjectCardGrid.tsx:43:11)
    at onContextMenu (ProjectCardGrid.tsx:125:47)
    at onClick (ProjectCard.tsx:121:25)
```

## 原因分析
1. **模拟事件对象缺陷**：在 `ProjectCard.tsx` 第115-119行，为了从按钮位置触发右键菜单，创建了一个模拟事件对象：
   ```typescript
   const mockEvent = {
       ...e,  // ❌ 对象展开只能复制属性，无法复制方法
       clientX: buttonRect.right,
       clientY: buttonRect.bottom,
   } as React.MouseEvent;
   ```

2. **方法继承失效**：JavaScript 对象展开操作符 `{...e}` 只能复制**可枚举属性值**，无法复制原型链上的方法（如 `preventDefault()`、`stopPropagation()`）。

3. **错误链路**：
   - 点击按钮 → 创建 `mockEvent` → 传给 `onContextMenu`
   - `ProjectCardGrid` 接收后调用 `handleContextMenu(e, projectId)`
   - 第43行执行 `e.preventDefault()` → **报错：不是函数**

## 解决方案
在 `ProjectCardGrid.tsx` 的 `handleContextMenu` 中添加**防御性检查**：
```typescript
const handleContextMenu = (e: React.MouseEvent, projectId: string) => {
    // 防御性检查：某些模拟事件对象可能没有 preventDefault 方法
    if (e.preventDefault && typeof e.preventDefault === 'function') {
        e.preventDefault();
    }
    // ... 其他逻辑
};
```

## 验证结果
- ✅ 点击"更多操作"按钮无报错
- ✅ 右键菜单正常弹出并定位在按钮附近
- ✅ 对真实的 `onContextMenu` 事件也兼容（仍会调用 `preventDefault()`）

## 策略标签
#事件对象传递 #方法继承缺失 #防御性编程
