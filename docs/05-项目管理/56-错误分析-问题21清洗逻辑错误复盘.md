# 错误分析卡片：问题#21 清洗建议执行逻辑错误

## 1. 问题背景
- **问题**：用户指出当前系统存在严重的**功能性失误**。虽然 AI 生成了清洗建议 SQL，但系统在执行时却丢弃了它，转而使用本地硬编码的模板。
- **影响**：
    1.  **所见非所得**：用户无法知道到底执行了什么。
    2.  **能力受限**：本地模板只能覆盖 `dedup`, `drop_col`, `fill` 等简单场景，无法支持 AI 生成的高级清洗逻辑（如 Regex 提取、Case When 分组）。
    3.  **信任危机**：对于专业分析师，不透明的 SQL 执行是不可接受的。

## 2. 根因分析
- **历史包袱**：`sqlBuilder.ts` 是在未接入 AI 前的规则引擎时代的产物。
- **集成遗漏**：在接入 `aiCleaningService` 时，只消费了 `label`, `reason` 等展示字段，未将核心的 `sql` 字段接入执行链路。

## 3. 修复方案
1.  **Types**: 修改 `SimpleSuggestion` 接口，增加 `sql` 字段。
2.  **Service**: 在 `aiCleaningService` 的转换逻辑中，保留 `sql`。
3.  **Execution**: 修改 `useCleaningExecution`。
    - **逻辑变更**：
      ```typescript
      // Before
      const sql = buildCleaningSQL(sugg);
      // After
      const sqlTemplate = sugg.sql || buildCleaningSQL(sugg); // 优先用AI SQL
      const sql = sqlTemplate.replace(/__TABLE_NAME__/g, tableName);
      ```
4.  **UI**: 修改 `SuggestionCard`，在展开区域添加 SQL 代码块展示。
