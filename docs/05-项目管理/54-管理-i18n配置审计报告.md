# i18n 配置审计报告

**审计日期**: 2025-12-28
**审计对象**: Prompt Library i18n Configuration
**关联规则**: 全局规则 #1 (样式变量), #2 (国际化), #10 (错误复盘)

## 1. 为了诊断问题 (Problem Diagnosis)

### 现状分析
- **UI表现**: 导航栏显示 raw key `prompt.library.title`。
- **文件状态**: `src/locales/zh-CN/prompt.ts` 和 `en-US/prompt.ts` 中，原计划的 `library` 嵌套对象被意外扁平化，导致 key 路径不匹配。

### 关键发现 (Key Findings)
通过对代码和资源文件的对比审计，发现以下键值路径不一致：

| 组件文件 (Component) | 调用路径 (Usage) | 当前资源文件路径 (Actual) | 状态 (Status) |
| :--- | :--- | :--- | :--- |
| `NavigationBar.tsx` | `prompt.library.title` | `prompt.title` | ❌ Mismatch |
| `LibrarySidebar.tsx` | `prompt.library.filter.*` | `prompt.filter.*` | ❌ Mismatch |
| `LibrarySidebar.tsx` | `prompt.sidebar.*` | `prompt.sidebar.*` | ✅ Match |
| `PromptCard.tsx` | `prompt.library.card.*` | `prompt.card.*` | ❌ Mismatch |
| `PromptDetailModal.tsx` | `prompt.detail.*` | `prompt.detail.*` | ✅ Match |

## 2. 修复方案 (Remediation Plan)

为了最小化对组件代码的修改风险，决定调整资源文件 (`prompt.ts`) 的结构以匹配现有代码的调用预期。

### 结构调整
将以下字段重新通过 `library` 对象包裹：
- `title`
- `description`
- `searchPlaceholder`
- `filter`
- `card`

保留以下字段在根节点 (Root Level)：
- `sidebar`
- `detail`
- `category`
- `action`
- `examples`
...

## 3. 预防措施 (Prevention)

1.  **类型强化**: 建议后续为 `props.t` 增加更严格的类型检查（目前是基于 i18next loose typing）。
2.  **变更审查**: 修改 i18n 文件时，必须同时搜索全局引用，确保路径一致。
