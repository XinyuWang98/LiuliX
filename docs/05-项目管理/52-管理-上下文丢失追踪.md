## 📋 2025-12-19 19:20 - 预处理优化方案三项改进

### 场景
对预处理优化方案进行三项改进：
1. **洞察缓存失效机制**：清洗后自动刷新洞察假设
2. **大文件采样处理**：AI调用仅传入head(1000)
3. **AI失败兜底UI**：status='failed'时显示重试按钮

### 识别到的上下文丢失风险

#### 🔴 高风险：洞察节点突然消失

**触发条件**：
- 用户在"洞察链分析"模块查看某个假设的洞察节点（InsightNode）
- 切换到"数据清洗"模块执行清洗操作
- 改进1会触发 `invalidateInsightCache()`，将 `analysisCache.insight.hypotheses` 清空
- 用户切回"洞察链"时，所有洞察节点消失

**丢失内容**：
- `InsightChainContext` 中的 `insights` 数组（用户已生成的洞察节点）
- `activeHypothesisId` 状态（用户当前选中的假设）

**根本原因**：
- `ProjectContext.analysisCache.insight.hypotheses`（缓存层）与 `InsightChainContext.insights`（展示层）**跨Context通信不当**
- 清洗执行逻辑直接清空缓存，未考虑UI状态保留

#### 🟡 中风险：采样标记缺失

**触发条件**：
- 大文件（10万行）上传后，后台调用 `generateHypotheses(head(1000))`
- 但缓存中无 `basedOnSample` 标记
- 用户误以为建议基于全量数据

**丢失内容**：
- 采样来源信息（用户不知道建议基于采样数据，可能做出错误决策）

#### 🟢 低风险：失败状态未持久化

**触发条件**：
- AI调用失败后，`analysisCache.cleaning.status = 'failed'`
- 用户刷新页面，ProjectContext重新初始化
- 失败状态丢失，用户可能重复触发失败请求

**丢失内容**：
- 失败状态（如果未持久化到IndexedDB）

### 解决方案

#### ✅ 方案1：洞察缓存失效 - 软重置（已采纳）

**策略**：不清空 `hypotheses` 数组，而是添加 `isStale: true` 标记。

**实现细节**：
```typescript
// ProjectContext 中新增方法
const invalidateInsightCache = (fileId: string) => {
  updateFileAnalysis(fileId, {
    insight: {
      ...currentCache.insight,
      status: 'pending',
      isStale: true,        // ✨ 标记为过时，但保留数据
      staleSince: Date.now()
    }
  });
};

// InsightChainFlow.tsx 中响应
useEffect(() => {
  const cache = file.analysisCache?.insight;
  if (cache?.isStale) {
    // 显示提示："数据已清洗，正在重新分析..."
    // 旧假设卡片半透明显示，禁用点击
  }
}, [file.analysisCache]);
```

**避免的问题**：
- ✅ 洞察节点不会突然消失
- ✅ 用户能看到"正在更新"的过渡状态
- ✅ 旧数据在新数据到达前仍可查看

#### ✅ 方案2：采样标记 - 独立字段记录（已采纳）

**策略**：在 `analysisCache` 中添加 `basedOnSample` 元数据。

**实现细节**：
```typescript
// src/types/project.ts 扩展
interface AnalysisCache {
  cleaning: {
    suggestions: CleaningSuggestion[];
    status: 'pending' | 'ready' | 'failed';
    basedOnSample?: {      // ✨ 新增
      isSampled: boolean;
      sampleSize: number;
      totalSize: number;
    };
  };
  insight: {
    hypotheses: Hypothesis[];
    status: 'pending' | 'ready' | 'failed';
    isStale?: boolean;
    basedOnSample?: {      // ✨ 新增
      isSampled: boolean;
      sampleSize: number;
    };
  };
}
```

**避免的问题**：
- ✅ 用户能清晰看到"基于1000行采样数据分析"的提示
- ✅ 不与文件级别的 `is_sampled` 混淆

#### ✅ 方案3：失败状态持久化 - IndexedDB集成（已采纳）

**策略**：在 `updateFileAnalysis` 中自动写入IndexedDB。

**实现细节**：
```typescript
// ProjectContext 中增强
const updateFileAnalysis = async (fileId: string, data: Partial<AnalysisCache>) => {
  // 1. 更新内存状态
  setProjects(prev => /* ... */);
  
  // 2. 持久化到IndexedDB
  await indexedDB.saveFileCache(fileId, data);

```

**避免的问题**：
- ✅ 刷新页面后失败状态仍存在
- ✅ "重试"按钮持久显示，直到用户主动重试成功
