# 设备迁移指南 (Windows -> MacBook)

> [!IMPORTANT]
> 本文档专为将 DataPrism (LiuliX) 开发环境从 Windows 迁移至 MacBook (Apple Silicon/Intel) 设计。
> 确保在旧设备彻底格式化前，已备份所有“非 Git 追踪”的关键文件。

## 1. 系统环境准备

在 MacBook 上，我们需要配置 Node.js、Python 和 AI 运行时环境。

### 1.1 基础工具安装
推荐使用 Homebrew 进行管理。

```bash
# 安装 Homebrew (如果未安装)
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# 安装基础依赖
brew install git node python vscode
```

### 1.2 AI 环境 (Ollama)
LiuliX 依赖 Ollama 运行本地模型。

1. **下载**: 访问 [ollama.com](https://ollama.com) 下载 macOS 版本。
2. **安装**: 将应用拖入 Applications 文件夹。
3. **启动**: 运行 Ollama 应用，并按照引导完成命令行工具安装。
4. **拉取核心模型**:
   ```bash
   ollama pull qwen2.5:7b      # 推荐的主力模型
   ollama pull nomic-embed-text # 向量模型 (如果主要用这个)
   ```

### 1.3 Apple Silicon (M1/M2/M3) 专项准备 (Critical)

M 芯片架构与 Intel 不同，虽然大部分软件已适配，但以下准备工作能避免 90% 的“莫名其妙报错”。

1.  **安装 Rosetta 2**:
    虽然我们尽量用原生应用，但某些旧的 npm 包或底层依赖可能仍需转译。
    ```bash
    softwareupdate --install-rosetta
    ```

2.  **安装 Xcode Command Line Tools**:
    `npm install` 编译原生模块（如 `sharp`, `canvas` 或 Python 扩展）时的必备工具。
    ```bash
    xcode-select --install
    ```

3.  **确认终端架构**:
    确保你的 Terminal/iTerm2 **不是** 以 Rosetta 模式运行的。
    输入 `arch`，应返回 `arm64`。如果返回 `i386`，请检查终端应用属性。

4.  **Python 编译环境**:
    如果后续需要本地运行 Python 脚本（非 Pyodide 环境），建议设置编译标志以防 `pip install` 失败：
    ```bash
    export CFLAGS="-I$(brew --prefix openssl)/include"
    export LDFLAGS="-L$(brew --prefix openssl)/lib"
    ```

## 2. 项目代码迁移

### 2.1 获取代码
```bash
git clone <repository-url>
cd DataPrism_antigravity
```

### 2.2 安装依赖
本项目包含前端和后端两个部分，都需要安装依赖。

```bash
# 1. 安装前端依赖
npm install

# 2. 安装后端依赖 (Server Proxy)
cd server
npm install
cd ..
```

## 3. 恢复非 Git 追踪文件 (Critical)

以下文件被 `.gitignore` 忽略，无法通过 git拉取，必须手动恢复或重新生成。

### 3.1 环境变量 (.env)

项目根目录和 server 目录都需要独立配置 `.env` 或 `.env.local` 文件。请根据以下清单检查：

#### A. 根目录 (`.env.local`)
主要用于前端特性开关。

```ini
# 功能开关 (Feature Flags)
VITE_FEATURE_MULTI_LEVEL_NAV=true
```

#### B. Server 目录 (`server/.env.local`)
**这是最关键的部分**，包含所有敏感 API Key 和后端配置。

```ini
# 核心服务配置
PORT=3001
PROXY_PORT=5000 
FRONTEND_URL=http://localhost:5173

# AI 模型 API Keys (DeepSeek)
# 注意: 如果只配置了 DEEPSEEK_API_KEY，清洗和洞察都会使用如果不配，
DEEPSEEK_API_KEY=sk-xxxxxx
DEEPSEEK_API_KEY_CLEANING=sk-xxxxxx (可选，独立通道)
DEEPSEEK_API_KEY_INSIGHT=sk-xxxxxx (可选，独立通道)

# 免费试用与限制 (可选)
ENABLE_FREE_TRIAL_LIMIT=true
FREE_TRIAL_CLEANING_LIMIT=5
FREE_TRIAL_INSIGHT_LIMIT=5
INVITE_CODE_TOTAL_LIMIT=20
VALID_INVITE_CODES=CODE1,CODE2
```

> [!WARNING]
> 为了安全起见，切勿将包含真实 API Key 的文件提交到 Git 仓库。请通过 USB、AirDrop 或安全笔记应用（如 1Password）点对点传输这些文件。

### 3.2 Pyodide 离线包 (Public Assets)
`public/pyodide` 目录下的 `.whl` 和 `.tar.bz2` 文件被忽略。
**Mac 恢复步骤**:
不要直接复制 Windows 下载的文件，建议重新下载以确保完整性。

```bash
cd public/pyodide
# 运行下载命令 (替代 Windows 的 download.ps1)
curl -L https://github.com/pyodide/pyodide/releases/download/0.26.4/pyodide-0.26.4.tar.bz2 -o pyodide.tar.bz2
tar -xf pyodide.tar.bz2 --strip-components=1
rm pyodide.tar.bz2
```
> [!NOTE]
> 确保 `public/pyodide` 目录下有 `pyodide.js`, `pyodide.mjs` 和大量 `.whl` 文件。

### 3.3 本地模型缓存 (Optional)
检查 `models_cache/` 目录。如果不希望重新下载 GGUF 模型，可以从旧设备手动复制此文件夹到新设备根目录。

## 4. 验证与启动

### 4.1 启动全栈环境
推荐使用 `npm run dev:all` 同时启动前端和 API 代理服务。

```bash
# 在根目录运行
npm run dev:all
```

### 4.2 验证清单
- [ ] **前端页面**: 访问 `http://localhost:5173` (或终端显示的端口)，确保页面无白屏。
- [ ] **后端连接**: 检查终端中 `backend` 服务的日志，确保无报错。
- [ ] **AI 服务**:
    - 在设置页 -> AI配置，检查 Ollama 是否连接成功 (Mac 可能需要配置 `OLLAMA_ORIGINS="*"` 环境变量，如果在 docker 或特殊网络下)。
    - 尝试一次简单的 AI 对话或数据清洗建议。
- [ ] **Pyodide**: 进入“数据清洗”页面，检查 Python 环境是否初始化成功 (图标不转圈，控制台无报错)。

## 5. 常见问题 (Mac)

*   **Ollama 连接失败**: 
    确保 Ollama 正在后台运行（顶部菜单栏可见图标）。
*   **端口占用**: 
    macOS Control Center 有时占用 5000/7000 端口，如果 `dev:backend` 报错，尝试修改 `server/index.js` 端口或关闭 AirPlay Receiver。
*   **权限问题**:
    如果是 M1/M2/M3 芯片，确保 Node.js 是通过 arm64 架构运行的 (默认 brew 安装即可)，避免 Rosetta 转译带来的性能问题。
