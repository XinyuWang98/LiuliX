## 📋 P0 级别（阻塞发布）

### [P0-001] Pyodide Worker初始化竞态条件
**发现日期**: 2026-01-13  
**优先级**: P0  
**影响范围**: 新用户首次使用体验

**问题描述**:
用户首次上传数据并执行洞察分析时，所有洞察卡片执行失败（0/5成功）。用户重试第二次全部成功。

**根本原因**:
Pyodide Worker初始化流程存在竞态条件：
1. Worker启动 → `ready`标志置true （耗时~3秒）
2. 核心Python包（scipy/seaborn）仍在后台加载（耗时50-60秒）
3. 用户点击执行 → 代码找不到`scipy`模块 → 失败
4. 用户重试 → 包已加载完成 → 成功

**日志证据**:
```
[21:49:42.084] 开始执行 5个洞察
[21:49:45.524] 批量执行完成 {total: 5, successful: 0, failed: 5}  // ← 3秒全失败

[用户重试]
[21:50:33.287] 状态: Loading packages: matplotlib, numpy, pandas, scipy...
[21:50:55.511] 部分包完成（耗时22秒）
[21:51:26.584] 所有包完成（总耗时53秒）
[21:51:37.809] 洞察成功 {total: 5, successful: 5}  // ← 全部成功
```

**修复方案**:
1. **方案A（推荐）**: Worker初始化时预加载所有常用包，完成后才标记`ready`
   - 文件: `src/services/python/PyodideWorkerManager.ts`
   - 修改: `initWorker()`等待`scipy`/`seaborn`加载完成
   - 优点: 彻底解决，用户无感知
   - 缺点: 首次加载时间+50秒

2. **方案B**: UI显示包加载进度，禁用"执行"按钮直到就绪
   - 文件: `InsightChainFlow.tsx`
   - 修改: 监听Worker加载状态，显示进度条
   - 优点: 用户体验清晰
   - 缺点: 仍需等待，UI改动大

3. **方案C**: 失败时自动重试，静默处理
   - 文件: `executor.ts`
   - 修改: 捕获`ModuleNotFoundError`，延迟5秒重试
   - 优点: 改动最小
   - 缺点: 治标不治本，延迟不可预测

**推荐**: 方案A + 方案B组合
- 预加载常用包
- 显示"正在初始化Python环境..."加载提示

**计划修复日期**: 2026-01-14  
**负责人**: Agent
