## 1. 拆分记录 (2025-12-21)

### 1.1 `src/components/layout/LeftSidebar.tsx`

**【文件分析卡片】**
- **文件路径**：`src/components/layout/LeftSidebar.tsx`
- **当前行数**：777行
- **主要逻辑**：负责侧边栏的项目管理、文件树渲染、文件上传、右键菜单、AI状态展示、重命名/删除交互。
- **行数超标原因**：
  1. **UI组件耦合**：文件树渲染 (`renderTree`)、项目列表渲染 (`projects.map`)、右键菜单 (`ContextMenu`) 全部写在同一个文件中。
  2. **状态逻辑复杂**：包含大量 `useState` (expanded, renaming, contextMenu, upload...) 和 `useEffect` (AI status check)。
  3. **内联样式混杂**：虽然提取了部分 CSS，但仍有大量内联样式逻辑。

**【拆分方案建议】**

**方案 A：功能组件拆分 (推荐)**
将大组件拆分为独立的子组件，保持 `LeftSidebar` 作为容器和状态管理者。
- `src/components/layout/sidebar/SidebarHeader.tsx`: 顶部标题、搜索框、添加按钮。
- `src/components/layout/sidebar/ProjectList.tsx`: 项目列表渲染逻辑。
- `src/components/layout/sidebar/FileTreeItem.tsx`: 单个文件/文件夹节点的渲染 (递归或列表项)。
- `src/components/layout/sidebar/SidebarContextMenu.tsx`: 右键菜单组件。
- `src/components/layout/sidebar/EmptyState.tsx`: 无项目时的空状态。

**方案 B：逻辑 Hook 提取**
仅提取逻辑，保留 JSX。
- `useSidebarLogic.ts`: 包含所有 `useState` 和事件处理函数。

**【预估收益】**
- 主文件行数降至 < 200 行。
- `FileTreeItem` 可复用，性能优化更方便 (React.memo)。
- 维护性大幅提升。

**【执行结果】**
- ✅ 已执行方案 A (组件拆分)
- **拆分前**: 780行 (UI耦合严重)
- **拆分后**: ~480行 (合规)
- **产物**:
  - `src/components/layout/LeftSidebar.tsx` (核心状态容器)
  - `src/components/layout/sidebar/SidebarHeader.tsx`
  - `src/components/layout/sidebar/ProjectItem.tsx`
  - `src/components/layout/sidebar/FileTreeItem.tsx`
- **验证**: `npm run type-check` 通过。
