# MVP上线前待办：内存动态评估UI文案补充

## 📋 问题描述

当前系统有**两个独立的采样系统**，但用户界面中只暴露了一个（AI采样），另一个（内存动态评估）完全隐藏在代码层面，容易造成用户困惑。

---

## 🔍 现状分析

### 系统1：AI采样（已有UI）

**位置**：设置 → 性能与质量 → 数据分析策略

**UI展示**：
```
○ 快速模式（开发中）
  AI采样：500行 | 推理时间：~3秒

● 平衡模式（当前MVP）【默认】
  AI采样：1000行 | 推理时间：~5秒

○ 精确模式（开发中）
  AI采样：2500行 | 推理时间：~10秒
```

**作用**：控制发送给AI的样本数据行数，影响AI生成建议的质量

**实现**：`sampleDataForAI(tableName, limit)`

---

### 系统2：内存动态评估（无UI）

**位置**：代码层面，用户无感知

**实现文件**：
- `src/utils/memoryAssessment.ts` - 内存评估逻辑
- `src/utils/resourceLimits.ts` - 资源限制配置
- `src/services/insights/executor.ts` - 执行时应用

**作用**：根据浏览器内存动态决定Pyodide执行时的数据采样
- 4GB内存 → 最多30,000行
- 8GB内存 → 最多50,000行  
- 16GB内存 → 最多100,000行

**决策逻辑**：
```typescript
// 内存占比 < 20% → full模式（全量）
// 内存占比 20-50% → sampled模式（采样）
// 内存占比 > 50% → aggregated模式（DuckDB预聚合）
```

---

## ⚠️ 用户困惑点

1. **设置页显示"AI采样：1000行"，但执行时可能加载20000行**
   - 用户以为所有操作都用1000行
   - 实际上执行时由内存评估自动决定

2. **下钻场景无任何提示**
   - 用户点击下钻后卡顿40秒（修复前）
   - 不知道系统在用20000行数据跑时序分析
   - 不知道有采样机制可以加速

3. **性能与质量的权衡不透明**
   - 用户无法理解为什么有时快有时慢
   - 无法知道当前使用的是哪种模式

---

## 💡 建议方案

### 方案A：状态指示器（最小改动）

在洞察卡片上添加徽章显示执行模式：

```
┌─────────────────────────────────┐
│ 🔬 分析温度数据的分布特征        │
│ [全量 20k行] or [采样 5k/20k行]  │
└─────────────────────────────────┘
```

**优点**：让用户知道当前使用的数据量
**缺点**：不可配置

---

### 方案B：性能模式选择器（推荐）

在设置页的"数据分析策略"下方，增加"执行性能"配置：

```
数据分析策略（AI建议生成）
○ 快速模式  AI采样：500行
● 平衡模式  AI采样：1000行
○ 精确模式  AI采样：2500行

────────────────────────────

执行性能（代码运行）
● 自动模式（推荐）
  根据浏览器内存自动决定采样策略
  当前配置：8GB内存 → 最多50,000行

○ 手动限制
  [ ] 强制限制最大行数
  [5000] 行（避免卡顿，但可能影响精度）
```

**优点**：
- 让用户理解两套系统的区别
- 保留自动模式的智能性
- 给高级用户手动控制的选项

**缺点**：增加UI复杂度

---

### 方案C：智能提示（折中方案）

在执行耗时操作前，显示Toast提示：

```
⏳ 正在分析20,000行数据（时序分解）
   预计需要30-40秒，请稍候...

   💡 提示：可在设置中启用采样模式加速
```

**优点**：非侵入式，教育用户
**缺点**：可能被忽略
