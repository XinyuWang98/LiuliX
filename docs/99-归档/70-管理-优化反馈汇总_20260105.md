### F-01: ProjectCard 标题溢出优化

**问题描述**:
在 active 状态下的 `project-card` 中，当项目标题过长时（如 "Synthetic online communities 2025 项目"），`card-title` 会撑开布局或被截断得不美观。

**证据**:
- 用户截图与 HTML 结构显示 `card-title` 为普通块级元素，缺乏溢出控制。

**优化方案**:
1. **CSS 截断**: 对 `.card-title` 应用单行省略样式。
   ```css
   .card-title {
     overflow: hidden;
     text-overflow: ellipsis;
     white-space: nowrap;
     flex: 1; /* 确保占据剩余空间 */
     min-width: 0; /* Flex 布局防溢出关键 */
   }
   ```
2. **Tooltip**: HTML 标签已自带 `title` 属性，保留即可。
3. **范围**: 需检查 `src/components/exploration/ProjectCard.css`。

**问题描述**:

     ```tsx
     const displayValue = formatSmartNumber(stat.min);
     ```

### F-17: CSV 上传报错 (DuckDB max_line_size)

**问题描述**:
用户上传 `tokopedia_products_with_review.csv` (约 3MB) 时报错：
1. `analyzeCSV` 阶段报错 `Parser Error: syntax error at or near "("`。
2. `ingestCSV` 阶段报错 `Maximum line size of 2000000 bytes exceeded`。
建议调整 `max_line_size`。

**原因分析**:
1. **Analyze Error**: `DESCRIBE read_csv_auto(...)` 语法在 DuckDB WASM 中可能不支持，应改为 `DESCRIBE SELECT * FROM read_csv_auto(...)`。
2. **Ingest Error**: 虽然代码中已有 `max_line_size=10485760` (10MB)，但可能因 `analyzeCSV` 失败导致流程异常，或者默认 2MB 限制未被正确覆盖。考虑到文件可能含超长行（单行 3MB），需将限制提升至 50MB。

**优化方案**:
1. 修正 `analyzeCSV` 中的 SQL 语法。
2. 将 `max_line_size` 统一提升至 `50 * 1024 * 1024` (50MB)。

### F-19: 下钻卡片图片加载失败 (431 Request Header Too Large)

**问题描述**:
点击洞察分析下钻按钮后：
1. 左侧卡片的图片区域显示"图片加载失败"
2. 右侧 Live Notebook 有代码显示（正常）
3. 控制台报错：`Failed to load resource: the server responded with a status of 431 (Request Header Fields Too Large)`

**证据**:
- 用户截图显示图片加载失败
- 日志显示：`lMu+an97hWsAAAAASUVORK5CYII=:1  Failed to load resource: the server responded with a status of 431`
- Base64 编码的图片 URL 过长，超过浏览器/服务器限制

**原因分析**:
1. **图片内联方式问题**：图片可能使用 base64 data URI 直接内联在 HTML/URL 中
2. **URL 长度限制**：浏览器对 URL 长度有限制（通常 2048 字符），base64 编码的图片通常远超此限制
3. **请求头限制**：如果图片通过请求头传递，服务器可能设置了 `large_client_header_buffers` 限制

**优化方案**:
1. **改用 Blob URL**：将 base64 图片转为 Blob，使用 `URL.createObjectURL()` 创建本地引用
   ```typescript
   const blob = base64ToBlob(base64Data, 'image/png');
   const blobUrl = URL.createObjectURL(blob);
   ```
2. **图片缓存到 IndexedDB**：对于下钻生成的图片，存入 IndexedDB 并返回 key，按需读取
3. **使用 Canvas 渲染**：如果图片在前端生成，直接渲染到 Canvas 元素，避免数据 URL

**涉及文件**:
- `src/components/insights/InsightCardV2.tsx` (下钻卡片渲染)
- `src/components/insights/ChartImage.tsx` (图片组件)
- `src/services/skills/modeExecutor.ts` (图片生成逻辑)
