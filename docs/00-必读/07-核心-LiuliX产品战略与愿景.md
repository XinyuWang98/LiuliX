# 07-核心-LiuliX产品战略与愿景

> **文档性质**: 产品战略规划、商业模式设计、长期愿景
> **创建日期**: 2025-12-25
> **适用范围**: C端产品 → 社区生态 → B端企业版 完整演进路线

## 1. 产品定位

### 1.1 核心价值主张

**让数据分析师从"写代码"升级为"做选择"**

*   **Web 版**: 零配置，秒开即用，连接云端最强大脑 (DeepSeek/Grok)。
*   **离线版**: 物理隔离，极致隐私，解锁本地算力 (Qwen/Llama)。

| 传统模式 | LiuliX 模式 |
|----------|------------|
| 打开 Python/SQL | 点击预置分析卡片 |
| 手写分析代码 | AI 自动生成 |
| 反复调试 | 一键执行 |
| 手动整理报告 | 自动生成洞察 |

### 1.2 目标用户

| 用户类型 | 特征 | 核心诉求 |
|---------|------|---------|
| **初级分析师** | 1-2年经验，会 Excel | 快速上手，有模板可参考 |
| **资深分析师** | 3-5年经验，会 Python/SQL | 效率提升，沉淀方法论 |
| **业务分析师** | 非技术背景 | 不写代码也能分析 |
| **数据团队负责人** | 管理多人团队 | 知识沉淀，协作效率 |

## 3. 双轨社区生态

### 3.1 内容矩阵

```
┌──────────────────────────┬───────────────────────────────┐
│   🧠 Prompt 模板库       │     📊 分析案例库              │
│   (工具层)               │     (应用层)                   │
├──────────────────────────┼───────────────────────────────┤
│ 可复用的分析方法         │ 完整的分析过程                 │
│ 抽象的模板               │ 具体的案例                     │
│ 输出: 代码/SQL           │ 输出: 洞察报告                 │
│ 价值: "怎么分析"         │ 价值: "别人怎么分析的"         │
└──────────────────────────┴───────────────────────────────┘
```

### 3.2 分析案例结构

每个案例包含：
- **数据描述**: 数据背景和业务场景（脱敏）
- **分析过程**: 步骤链，每步关联使用的 Prompt
- **结论洞察**: 核心发现和业务建议
- **复用信息**: 使用的 Prompt 列表、难度标签

### 3.3 与 Prompt 库的联动

| 场景 | 联动方式 |
|------|---------|
| 案例 → Prompt | 案例中使用的 Prompt 可一键跳转查看/复用 |
| Prompt → 案例 | Prompt 详情页展示"使用此 Prompt 的案例" |
| Fork 案例 | 自动导入数据结构 + 关联 Prompt |
| 创作激励 | 案例使用量计入 Prompt 作者分成 |

## 5. 知识产权与授权

> ⚠️ **重要**: 必须在用户协议中明确 Prompt 的版权归属和平台使用权。

### 5.1 核心原则

| 权利类型 | 归属 | 说明 |
|----------|------|------|
| **著作权** | 创作者保留 | Prompt 的知识产权归创作者所有 |
| **使用权** | 平台获得授权 | 用户发布即授权平台分发 |
| **商业使用权** | 按可见性区分 | 见下文详细说明 |

### 5.2 按可见性的授权范围

| 可见性 | 平台权利 | To-B 复用 | 说明 |
|--------|---------|----------|------|
| **Private** | ❌ 无权使用 | ❌ 不可 | 仅用户自己可见 |
| **Team** | ⚠️ 团队内使用 | ❌ 不可 | 仅限该团队 |
| **Public (免费)** | ✅ 社区展示 | ⚠️ 需明确授权 | To-B 需额外授权 |
| **Public (付费)** | ✅ 商业分发 | ✅ 可 (含分成) | 用户已同意商业使用条款 |

### 5.3 To-B 复用策略

| 内容来源 | To-B 可用性 | 条件 |
|----------|------------|------|
| 官方内置 Prompt | ✅ 直接使用 | 平台自有 |
| 社区付费 Prompt | ✅ 可使用 | 用户已授权商业使用 |
| 社区免费 Prompt | ⚠️ 需单独授权 | 联系创作者获取商业授权 |
| 私有/团队 Prompt | ❌ 不可使用 | 用户未授权 |

## 6. 监控看板扩展

> **核心价值**: 从"短平快一次性分析"演进到"长期指标监控"。

### 6.1 产品逻辑

```
探索分析 (短平快)                    监控看板 (长期追踪)
┌─────────────────────┐            ┌─────────────────────┐
│ 一次性洞察           │     →      │ 持续监控指标         │
│ "这个月销量怎么样？"  │    固化    │ "每周自动刷新销量趋势" │
│                     │     →      │                     │
│ 验证假设 → 得出结论  │            │ 结论 → 持续追踪      │
└─────────────────────┘            └─────────────────────┘
```

### 6.2 用户流程

1. **完成分析** → 得到洞察结论
2. **固化洞察** → 点击"固化到监控看板"
3. **配置刷新** → 选择数据源和刷新频率
4. **持续监控** → 自动执行代码、更新图表
5. **变化告警** → 指标异常时通知用户

### 6.3 核心能力

| 能力 | 说明 |
|------|------|
| **代码复用** | 复用 Prompt 生成的 Python 代码 |
| **定时执行** | 每日/每周自动刷新 |
| **数据源绑定** | 用户维护数据源，定期更新 |
| **变化检测** | 同比/环比变化、阈值告警 |
| **历史快照** | 保留历史结果，可回溯 |

### 6.4 与探索分析的关系

| 组件 | 复用方式 |
|------|---------|
| Prompt 模板 | 监控卡片记录使用的 promptId |
| Python 代码 | 直接复用生成的代码，定时执行 |
| 可视化组件 | 复用洞察卡片的图表渲染 |
| 数据源 | 用户维护，定期刷新 |

## 10. 核心差异化与竞品对标 (2026.01 战略对话录)

> **背景**: 2026年1月，针对 LiuliX 的核心壁垒与 Hex/Quadratic 等竞品进行了深度对标，明确了“本地优先”的战略护城河。

### 10.1 核心定位：LiuliX 是谁？

我们明确了 LiuliX 并非另一个 ChatBot，而是一个 **“本地优先的 AI 数据工作台”**。

*   **差异化壁垒 (Trust)**:
    *   **极致隐私**: 通过 WASM 和 Pyodide 实现数据不出浏览器的极致隐私。
    *   **可控性**: 通过 **AST 静态分析** 和 **Dry Run（预演）** 机制，解决了通用 AI “乱改数据”的信任危机。
*   **形象比喻**:
    *   ChatGPT: “不可控的外包顾问”
    *   LiuliX: “关在本地会议室、严谨且自带电脑的实习生”

### 10.2 竞品对标：为什么 Hex 和 Quadratic 无法模仿我们？

| 维度 | Hex (Cloud Notebook) | Quadratic (Infinite Spreadsheet) | LiuliX (Local Workstation) |
| :--- | :--- | :--- | :--- |
| **DNA** | **Cloud-First** (协作优先) | **Cloud-First** (自由优先) | **Local-First** (隐私优先) |
| **商业模式** | 卖云端算力/API差价 | 早期SaaS模式 | 卖工具/私有化部署 (边缘计算) |
| **致命伤** | 必须上传数据，无法服务红线行业 | 同样依赖云端，难以彻底本地化 | 协作便利性弱于云端 (需 V4 补齐) |
| **胜负手** | 赢在协作 | 赢在自由度 | **赢在安全与可控** |

*   **结论**: 竞品靠“卖云端算力”赚钱，决定了它们无法通过“极致本地化”来革自己的命。我们在金融、医疗等“红线数据”场景拥有绝对的主场优势。

### 10.3 战略演进：LiuliX Enterprise 的未来形态 (边缘计算架构)

将 LiuliX 从单兵工具升级为企业基础设施的**“企业内网分发 + 边缘计算”**构想。

*   **新架构**:
    *   **中心节点**: 企业内网服务器 (负责分发应用 + 托管私有大模型)。
    *   **边缘节点**: 分析师的高性能笔记本 (负责计算 + 数据驻留)。
*   **降维打击**: 利用企业已有的终端算力 (员工电脑)，以极低的成本实现了竞品需要昂贵服务器集群才能做到的私有化部署。
*   **混合算力**: 小任务在浏览器跑 (零延迟)，大任务自动路由到内网集群跑 (破性能瓶颈)。

### 10.4 核心战略补完：破解“协作断层”与“熵增” (Web版与离线版的辩证关系)

针对上述提到的薄弱环节，我们明确了**“Web版先行，离线版收割”**的战术路径以及**“Prompt 即指标”**的治理思路。

#### 1. 解决“指标熵增”：Prompt as Metric
*   **问题**: 边缘计算架构下，如何保证分散在员工电脑上的计算口径一致？
*   **解法**: **将 Prompt 视为“封装好的指标口径”**。
    *   **定义**: “毛利率计算”不再是一段混乱的 SQL 或 Python 代码，而是一个经过总部审核的、版本受控的 Prompt 模板（`Metric-GrossMargin-v1.2`）。
    *   **分发**: 通过 Git/配置中心将这些“标准 Metric Prompt”强制推送到员工的 LiuliX 客户端。
    *   **执行**: 员工无需关心计算细节，只需调用该 Prompt，本地 AI 自动按标准口径执行分析。

#### 2. 解决“协作断层”：Web 版的双重使命
我们为什么优先上 Web 版而不是直接做离线版？
*   **Web 版 (Community & Growth)**:
    *   **角色**: **“资源工厂”与“流量漏斗”**。
    *   **任务**: 通过便捷的云端协作（解决协作摩擦）吸引 C 端用户，利用社区激励产生海量 Prompt 模板和分析案例（解决冷启动）。
*   **离线版 (Privacy & Enterprise)**:
    *   **角色**: **“价值收割”与“安全金库”**。
    *   **任务**: 直接复用 Web 版沉淀下来的优质资源（经过市场验证的 Prompt/案例），在企业内网进行高溢价变现。
*   **结论**: Web 版是为了**“造弹药”**（生产资源），离线版是为了**“卖军火”**（高价变现）。先有 Web 版的繁荣，才有离线版的厚度。
