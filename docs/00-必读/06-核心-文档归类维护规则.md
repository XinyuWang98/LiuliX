1. **所有markdown文档**必须归类到`docs/`下的6大分类目录

## 📝 命名规则详解

### 格式
```
序号-类别-中文名称.md
```

### 规则
1. **序号**: 两位数字，与分类对应
   - 00-必读: 01-09
   - 01-架构: 11-19
   - 02-日志: 21-29
   - 03-测试: 31-39
   - 04-专题: 41-49
   - 05-管理: 51-59

2. **类别**: 固定关键词
   - 核心、架构、日志、测试、专题、管理

3. **中文名称**: 
   - 简洁明了（3-8个字）
   - 突出主题
   - 避免特殊字符
   - 日志类建议带日期

### 示例对照表

| ❌ 错误命名 | ✅ 正确命名 |
|-----------|-----------|
| new_feature.md | 21-日志-新功能实现报告.md |
| test-report.md | 31-测试-功能验证报告.md |
| analysis_cache.md | 41-专题-缓存机制分析.md |
| bug_fix.md | 24-日志-P0问题修复报告.md |
| 文档1.md | 01-核心-项目概览.md |

## 🔄 新建文档工作流

### Step 1: 确定分类
根据文档用途，选择6大分类之一

### Step 2: 分配序号
- 查看该分类下现有文档的最大序号
- 新文档序号 = 最大序号 + 1
- 确保不超过分类范围（如01-架构最多到19）

### Step 3: 命名文档
按格式创建：`序号-类别-中文名称.md`

### Step 4: 放入目录
```bash
# 正确路径
docs/03-测试验证/36-测试-新功能验证.md

# 错误路径（禁止）
36-测试-新功能验证.md  # ❌ 根目录
docs/36-测试-新功能验证.md  # ❌ docs根目录
```

### Step 5: 更新导航
在`📚文档导航.md`中添加新文档条目

## 🚨 特殊规则

### 根目录文档限制
**只允许存在**:
1. `README.md` - 项目说明
2. `📚文档导航.md` - 总导航
3. 其他markdown文档**一律禁止**

### docs/根目录限制
**只允许存在**:
1. 6个分类子目录（00-必读 ~ 05-项目管理）
2. 图片资源（.svg, .png等）
3. 临时文档必须在24小时内归类

### 序号分配原则
1. **同类文档**: 按时间顺序递增
2. **跳号**: 允许（为后续插入留空间）
3. **重编号**: 避免（除非整体重构）

## 🔍 常见问题

### Q1: 一个文档可以属于多个分类怎么办？
**A**: 选择主要用途归类。如"性能测试报告"既可以是测试报告，也可以是技术专题，优先归入03-测试验证。

### Q2: 序号用完了怎么办？
**A**: 序号范围足够大（每类9个），如确实用完，可扩展到X0-X9（如20-29扩展为20-39）。

### Q3: 临时文档放哪里？
**A**: 
1. 短期临时（< 24h）: `docs/temp/`
2. 超过24小时必须归类或删除

### Q4: 英文文档名可以吗？
**A**: 不建议。除非是专有术语（如README），一律用中文。
