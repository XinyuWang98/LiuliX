【2025-12-14 下午】🐛 修复清洗后表被删除的严重bug
【问题描述】
* 用户执行清洗操作后，建议列表未生效，Console 出现 "Table does not exist" 错误
* 清洗操作本身成功（ALTER TABLE 执行成功），但随后表被删除

【根本原因】
* `duckdbEngine.ts` 的 `ingestCSV` 方法在每次调用时都会删除**所有**以 `t_` 开头的表（第114-133行）
* 清洗操作执行后，某个组件（如 DataViewer）触发了数据刷新，调用 `ingestCSV`，导致刚刚清洗过的表被删除
* 随后 DataCleaner 的 useEffect 尝试重新生成 AI 建议时，查询表失败

【修复方案】
* 修改表清理逻辑：只删除**即将创建的新表**（如果已存在），而不是删除所有旧表
* 这样可以保留清洗后的表，防止误删除
* 修改前：遍历所有表，删除所有 `t_` 开头的表（25行代码）
* 修改后：只执行 `DROP TABLE IF EXISTS ${tableName}`（3行代码）

* 修改 src/db/duckdbEngine.ts (移除第114-133行的激进表清理逻辑，改为只清理同名表)

#### 核心修复
```typescript
// 问题：使用旧表名
const tableName = currentFile.data.tableName; // t_1765702709316_working (已删除)
// ... DuckDB检测到最新表
// 但采样仍用旧表名导致失败 ❌

// 修复：动态更新表名
let tableName = currentFile.data.tableName;
if (latestTable) {
    const latestTableName = String(latestTable.table_name);
    if (tableName !== latestTableName) {
        console.log('[AI工坊] 🔄 更新tableName:', tableName, '→', latestTableName);
        tableName = latestTableName; // ✅ 使用最新表名
    }
}
```

#### 防重复点击
```typescript
const [isGenerating, setIsGenerating] = useState(false);

const handleToolClick = async () => {
    if (isGenerating) {
        console.log('[AI工坊] ⏸️ 正在生成中，请勿重复点击');
        return; // ✅ 阻止重复调用
    }
    setIsGenerating(true);
    try {
        // ... AI调用
    } finally {
        setIsGenerating(false); // ✅ 重置状态
    }
};
```
