## 背景问题

### 当前痛点
1. **重复采样严重**：洞察生成流程中采样7次，浪费约10秒
2. **策略判断错误**：100万行数据在16GB内存设备上仍走串行模式
3. **用户体验缺失**：上传采样20%时无UI提示
4. **数据浪费**：Executor每个洞察独立采样30万行×5次
5. **上传采样硬编码**：>20MB强制采样，未考虑设备内存能力

### 优化目标
- ✅ 采样次数从7次降到**1次**（减少86%）
- ✅ 100万行数据在16GB设备上启用并行模式
- ✅ Executor总耗时从~10秒降到~0.7秒（提速14倍）
- ✅ 用户清晰看到数据采样状态
- ✅ 上传阶段**完全基于内存动态评估**，移除硬编码条件

**问题诊断**：

#### [MODIFY] [executionStrategy.ts](file:///Users/catherinewang/Documents/GitHub/LiuliX/src/utils/executionStrategy.ts)

```typescript
export function assessExecutionStrategy(
    nodes: InsightNode[],
    totalRows: number
): ExecutionStrategy {
    const adapter = getPlatformAdapter();
    const config = getPlatformConfig();

    const browserMemory = adapter.getAvailableMemory();
    const optimalConcurrency = adapter.getOptimalConcurrency(nodes);

    // 估算任务内存占用
    const taskMemories = nodes.map(node =>
        estimateTaskMemory(node.promptId, totalRows)
    );
    const maxTaskMemory = Math.max(...taskMemories, 100);

    const parallel2Memory = maxTaskMemory * 2;
    const parallel3Memory = maxTaskMemory * 3;

    const ratio2 = parallel2Memory / browserMemory;
    const ratio3 = parallel3Memory / browserMemory;

    const { thresholds } = config;
    
    // 🆕 判断是否需要采样（提前计算）
    const needsSampling = totalRows > thresholds.samplingThreshold;
    const effectiveRows = needsSampling ? thresholds.samplingThreshold : totalRows;
    
    // ========== 策略1：高性能并行（优先级1）==========
    if (
        ratio3 < thresholds.highPerfMemoryRatio &&
        browserMemory >= thresholds.minMemoryForParallel
    ) {
        return {
            mode: 'parallel',
            concurrency: optimalConcurrency,
            sortByComplexity: true,
            enableSampling: needsSampling,  // 🆕 大数据集也支持并行+采样
            estimatedTime: estimateTotalTime(nodes, optimalConcurrency, effectiveRows),
            reason: needsSampling 
                ? `高性能并行+采样：内存${browserMemory}MB充足，${optimalConcurrency}并发，采样${effectiveRows}行`
                : `高性能并行：内存${browserMemory}MB充足，${optimalConcurrency}并发`
        };
    }

    // ========== 策略2：半并行+采样（优先级2）==========
    if (
        ratio2 < 0.5 &&
        browserMemory >= 8000  // 至少8GB
    ) {
        return {
            mode: 'parallel',
            concurrency: 2,
            sortByComplexity: true,
            enableSampling: needsSampling,
            estimatedTime: estimateTotalTime(nodes, 2, effectiveRows),
            reason: needsSampling
                ? `平衡并行+采样：2并发，采样${effectiveRows}行`
                : `平衡并行：2并发`
        };
    }

    // ========== 策略3：串行+采样（内存不足时）==========
    if (needsSampling) {
        return {
            mode: 'serial',
            concurrency: 1,
            sortByComplexity: true,
            enableSampling: true,
            estimatedTime: estimateTotalTime(nodes, 1, effectiveRows),
            reason: `串行+采样：内存有限(${browserMemory}MB)，采样${effectiveRows}行`
        };
    }

    // ========== 策略4：串行（兜底）==========
    return {
        mode: 'serial',
        concurrency: 1,
        sortByComplexity: true,
        enableSampling: false,
        estimatedTime: estimateTotalTime(nodes, 1, totalRows),
        reason: `串行模式：内存有限(${browserMemory}MB)`
    };
}
```

**影响范围**：
- 修改文件：1个
- 修改行数：约60行

### 模块5️⃣: 上传阶段纯内存评估采样 (P0 - 核心)

**问题诊断**：
```typescript
// ❌ 当前硬编码（duckdbIngestion.ts）
const shouldSample = fileSize > 20 * 1024 * 1024 && rowCount > 100000;
const sampleRate = 0.2;  // 固定20%
```

**优化方案**：
**完全移除硬编码条件**，基于内存动态评估最优采样行数

#### [MODIFY] [duckdbIngestion.ts](file:///Users/catherinewang/Documents/GitHub/LiuliX/src/db/duckdbIngestion.ts)

```typescript
export async function ingestCSV(
    db: any,
    conn: any,
    file: File,
    options?: IngestionOptions
): Promise<IngestionResult> {
    // ... 前置逻辑（获取tableName, rowCount等）

    // ========== 🆕 纯内存评估采样策略 ==========
    
    // Step 1: 快速获取列数（从CSV头部）
    const firstRowResult = await conn.query(`SELECT * FROM ${tableName} LIMIT 1`);
    const columnCount = firstRowResult.schema.fields.length;
    
    // Step 2: 根据列数和内存动态计算最优行数
    const { calculateMaxRowsForPyodide } = await import('@/utils/memoryAssessment');
    const maxRows = calculateMaxRowsForPyodide(columnCount);
    
    // Step 3: 判断是否需要采样（纯行数比较，无文件大小条件）
    const shouldSample = rowCount > maxRows;
    
    logger.log('DuckDB', `采样决策（纯内存评估）`, {
        data: {
            原始行数: rowCount,
            列数: columnCount,
            内存评估最大行数: maxRows,
            是否采样: shouldSample,
            决策依据: '基于设备内存动态计算'
        }
    });
    
    if (shouldSample) {
        // Step 4: 采样到maxRows行（而非固定百分比）
        const workingTableName = `${tableName.replace('_original', '')}_working`;
        
        await conn.query(`DROP TABLE IF EXISTS ${workingTableName}`);
        await conn.query(`
            CREATE TABLE ${workingTableName} AS 
            SELECT * FROM ${tableName} 
            LIMIT ${maxRows}
        `);
        
        const result = await conn.query(`SELECT COUNT(*) as count FROM ${workingTableName}`);
        const sampledRowCount = Number(result.toArray()[0].count);
        
        logger.log('DuckDB', `✅ 采样完成`, {
            data: {
                原始: rowCount,
                采样后: sampledRowCount,
                采样率: `${((sampledRowCount / rowCount) * 100).toFixed(1)}%`
            }
        });
        
        return {
            tableName: workingTableName,
            originalTableName: tableName,
            rowCount: sampledRowCount,
            originalRowCount: rowCount,  // 🆕 保留原始行数
            columns,
            isSampled: true,
            sampleStrategy: 'memory-based'  // 🆕 标记策略
        };
    }
    
    // Step 5: 不需要采样，创建working表（完整副本）
    const workingTableName = `${tableName.replace('_original', '')}_working`;
    await conn.query(`DROP TABLE IF EXISTS ${workingTableName}`);
    await conn.query(`CREATE TABLE ${workingTableName} AS SELECT * FROM ${tableName}`);
    
    return {
        tableName: workingTableName,
        originalTableName: tableName,
        rowCount,
        originalRowCount: rowCount,
        columns,
        isSampled: false
    };
}
```

**效果**：
- ✅ **完全移除硬编码条件**（20MB、100万行等）
- ✅ **纯内存评估**：根据设备内存和列数动态计算最优行数
- ✅ **统一采样策略**：上传阶段采样 = 洞察阶段所需，无重复采样
- ✅ **自适应**：8列数据在16GB设备可处理更多行，64列数据自动减少行数
