## 一、DuckDB 表名同步问题修复

### 1.1 问题描述

**现象**：
- 页面刷新后，`localStorage` 中存储的 `tableName` 失效
- 控制台报错：`Table with name t_xxx does not exist!`

**根本原因**：
- DuckDB 在浏览器内存中运行，数据不持久化
- 页面刷新后表被清空，但 `localStorage` 中仍保留旧表名
- 代码直接使用失效的 `tableName` 查询，导致错误

### 1.2 解决方案

**方案 A：预防性清理机制**（已实施）

1. **新增服务方法**：`DataLoadingService.cleanupInvalidTableName`
   - 文件：`src/services/dataLoadingService.ts` (L78-102)
   - 功能：检测 `tableName` 是否有效，若失效则清理并返回更新后的 Project
   
2. **修改数据加载流程**：`useDataLoader.ts`
   - 文件：`src/components/data/hooks/useDataLoader.ts` (L80-110)
   - 逻辑：在使用 `tableName` 前先调用清理方法，自动触发重新 ingest

3. **日志标准化**：
   - 将裸 `console.warn` 替换为 `logger.warn('DuckDB', 'tableName 失效，已清理', {...})`
   - 符合全局规则 #15

**验证结果**：
- ✅ 页面刷新后无 `DESCRIBE` 错误
- ✅ 数据自动重新加载
- ✅ 无需用户手动干预

## 三、下钻点击 tableName 缺失修复

- 点击下钻按钮（如"按时间聚合收入"）后报错

- 当 `tableName` 为 `undefined` 时，传递空字符串导致 `modeExecutor.ts` L76 抛出错误

### 3.2 解决方案

**修改文件**：`src/components/insights/InsightChainFlow.tsx`

```diff
  // ✅ 优先级：props.tableName > file.data.tableName > file.tableName
+ const effectiveTableName = tableName || file?.data?.tableName || file?.tableName;
+
+ if (!effectiveTableName) {

      {...},
```

## 四、图片 Base64 渲染问题修复

### 4.1 问题描述

**现象**：
- 下钻生成的图片无法显示
- 控制台错误：`GET http://localhost:5173/iVBORw0KGgo... 431 (Request Header Fields Too Large)`

**根本原因**：
- Pyodide 返回的是纯 Base64 字符串（`iVBORw0K...`）
- 缺少 `data:image/png;base64,` 前缀
- 浏览器将超长 Base64 字符串当作 URL 发送 HTTP 请求
- 请求 Header 超出服务器限制，触发 431 错误

### 4.2 解决方案

**1. 创建工具函数**：`src/utils/imageUtils.ts`（新建）

```typescript
export function formatChartBase64(base64?: string): string {
    if (!base64) return '';
    if (base64.startsWith('data:image')) return base64;
    return `data:image/png;base64,${base64}`;
}
```

**2. 批量修复组件**（共 4 个）：

| 组件 | 修改位置 | 修改内容 |
