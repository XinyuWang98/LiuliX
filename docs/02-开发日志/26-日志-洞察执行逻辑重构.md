# 26-日志-洞察执行逻辑重构

## 1. 背景与问题
**日期**: 2026-01-07  
**模块**: Insight (Live Notebook)  
**问题**: 用户在 Live Notebook 中切换 "纯净代码" (Pure Code) 和 "增强代码" (Enhanced Code) 时，显示的代码内容没有变化。尽管后端日志显示生成了不同的代码及 `rawCode`。

## 2. 根因分析
经过详细的代码审查和数据流追踪，发现问题根源在于**执行逻辑的分散与不一致**：

1.  **数据生成正常**: `inflater.ts` 正确生成了包含 `rawCode` (纯净版) 和 `code` (增强版) 的结果。
2.  **数据传递丢失**: 
    - 父系洞察卡片使用 `useInsightLoaderV2.ts` 中的内联循环进行执行。
    - 下钻卡片使用 `InsightChainFlow.tsx` 中的 `handleDrillDown` 进行执行。
    - 这两处逻辑各自独立实现，导致 `rawCode` 的保留逻辑不一致，且容易在后续维护中再次破损。
3.  **结果覆盖**: 在某些路径下，重新执行的代码结果覆盖了原始生成的 `rawCode`，导致前端收到的 `rawCode` 实际上是空的或与 `code` 相同（回退逻辑）。

## 3. 重构方案：统一执行器
为了彻底解决此问题并消除代码冗余，实施了以下重构：

### 3.1 引入公共执行模块 (`executor.ts`)
创建 `src/services/insights/executor.ts`，封装核心执行逻辑：
```typescript
interface ExecutionResult {
    success: boolean;
    result?: {
        code: string;
        rawCode?: string; // ✅ 显式保留
        image?: string;
        summary: string;
        // ...
    }
}
```

### 3.2 重构调用点
1.  **useInsightLoaderV2.ts**: 移除了约 80 行复杂的内联执行与错误处理代码，替换为 `executeBatchNodes` 调用。
2.  **InsightChainFlow.tsx**: 移除了下钻逻辑中的重复代码，替换为 `executeAndFillResult` 调用。

## 4. 变更文件清单
- `[NEW] src/services/insights/executor.ts`
- `[MOD] src/hooks/useInsightLoaderV2.ts`
- `[MOD] src/components/insights/InsightChainFlow.tsx`
- `[MOD] src/components/insights/LiveNotebookPanel.tsx` (移除调试日志)
- `[MOD] package.json` (相关校验脚本更新)

## 5. 验证结果
- **构建检查**: `npm run build` 通过，无类型错误。
- **服务状态**: 前后端服务正常启动。
- **功能验证**:
    - 洞察生成流程正常。
    - Live Notebook 代码切换功能恢复，可正确显示纯净/增强代码差异。
    - 下钻分析功能正常，且继承了代码切换能力。

## 6. 经验总结
- **DRY 原则 (Don't Repeat Yourself)**: 核心业务逻辑（如代码执行）必须统一封装，禁止分散在 UI 层。
- **数据流完整性**: 在涉及多阶段数据处理（Inflate -> Execute -> Display）时，必须确保辅助字段（如 `rawCode`）的全链路透传。
