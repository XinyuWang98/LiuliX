## 📋 背景

### 问题描述
AI生成的洞察分析代码频繁出现列名错误:
- `KeyError: 'id'`, `'value'`, `'column_name'` 等
- EDA闭环L2节点失败率高达80%
- 根本原因: AI生成占位符列名 + 父节点DataFrame状态丢失

### 初步诊断
- **P0拦截率**: 0% (所有错误直达Python执行层)
- **主要错误类型**:
  - 占位符: "需要指定实际列名"
  - 通用名: "id", "value", "category"
  - 临时列: "cluster_label"(父节点未持久化)

## 💻 技术实现

### 1. P1列名验证 (pythonColumnExtractor.ts)

**核心函数**:
```typescript
export function extractColumnNames(pythonCode: string): string[]
export function validateColumnReferences(
    pythonCode: string,
    actualColumns: string[]
): ValidationResult
```

**提取模式**:
- `df['column']` / `df["column"]`
- `df.column_name`
- 过滤pandas内置方法(shape, dropna等)

**占位符检测** (15种模式):
```typescript
/需要指定/, /请指定/, /实际列名/
/^column(_)?name$/i, /^your(_)?column$/i
/^xxx$/i, /^TODO/i, /\.\.\./
```

### 2. Executor集成 (executor.ts)

**验证流程**:
```
代码渲染 → 列名预验证 → 内存评估 → 代码执行
            ↓
     ┌─占位符? → 拦截
     └─列不存在? → 拦截
```

**错误消息示例**:
```
占位符: "代码包含占位符列名: 需要指定实际列名。这是AI生成错误..."
列不存在: "代码引用了不存在的列: id。可用列: longitude, latitude..."
```

### 3. P2框架 (dataframePersistence.ts)

**技术栈**:
- 存储: IndexedDB (idb库)
- 容量: ~50MB
- TTL: 30分钟自动过期
- 清理: 每10分钟自动执行

**API设计**:
```typescript
await DataFramePersistence.saveDataFrame(nodeId, dfJson)
const df = await DataFramePersistence.loadDataFrame(nodeId)
await DataFramePersistence.cleanupExpired()
```

**状态**: 框架完成,暂未集成到executor

### 关键发现

**问题**: `validatedColumns: Array(0)` - **正则提取失败**

```
[14:24:31.922] [AI服务] [洞察2] 列名验证通过 {validatedColumns: Array(0)}
```

**分析**:
1. 正则**未成功提取** 'id', 'category', 'value1'
2. 验证逻辑: "无列引用 → 默认通过" → **逻辑漏洞**
3. 'id', 'category' 看似真实列名,不是明显占位符

## ⚠️ 存在问题

### P1局限性

1. **正则覆盖不足**
   - 'id', 'category', 'value1' 未被提取
   - 可能原因: 代码中使用变量赋值或f-string

2. **"无列引用"逻辑漏洞**
   - 空数组视为"验证通过"
   - 应改为: 代码中有逻辑但未提取到列 → 警告

3. **占位符识别盲区**
   - 'id', 'category' 看似真实列名
   - 难以与合法列名区分
