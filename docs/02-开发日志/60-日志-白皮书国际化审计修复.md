> **日期**: 2026-01-13

## 1. 任务背景
在完成白皮书 (Whitepaper) 模块的独立路由与样式隔离后，运行 `check-hardcoded` 脚本发现了残留的硬编码字符串。同时，国际化 (i18n) 类型定义存在不同步问题。

## 2. 变更内容

### 2.1 国际化 (i18n) 修复
- **WhitepaperLayout**: 将硬编码的 `'zh'` / `'en'` 切换逻辑替换为 `t('language.zh')` / `t('language.en')`.
  - 修改前: `{language.code === 'zh-CN' ? '中文' : 'English'}`
  - 修改后: `{language.code === 'zh-CN' ? t('language.zh') : t('language.en')}`
- **Locale Files**:
  - `zh-CN/common.ts`: 新增 `language: { zh, en }`.
  - `en-US/common.ts`: 新增 `language: { zh, en }`.
  - `en-US/index.ts`: 修复了 `language` 对象的导出，确保与 `zh-CN` 结构对其。

### 2.2 类型同步修复 (TypeScript)
- **Problem**: `en-US/index.ts` 尝试导出 `language` 对象时，发现 `src/types/i18n.ts` 中的 `Language` 接口定义缺失 `zh/en` 字段。
- **Fix**: 更新 `src/types/i18n.ts`，为 `language` 节点添加 `zh: string; en: string;` 定义，符合**全局规则 #21 i18n 类型同步强制化**。

### 2.3 错误复盘 (Error Analysis)
- **事件**: 在修复 `en-US/index.ts` 时，不慎引入了重复的 `language` 属性定义，且在汇报时使用了英文。
- **处置**:
  1. 生成【错误分析卡片】并写入 `docs/05-项目管理/51-管理-错误日志记录.md`.
  2. 立即修复代码，移除冗余属性。
  3. 严格执行中文汇报规则。

## 3. 验证结果
- **类型检查**: `src/locales/en-US/index.ts` 无编译错误。
- **规则合规**: 所有代码修改遵循 `replace_file_content` 规范，文档使用中文。
