# 11. 反幻觉工程：LiuliX 的 Prompt 架构实践

> **最后更新**: 2026-01-13

> **概要**: 在数据分析领域，AI 的"幻觉" (Hallucination) 是不可接受的。本文档揭示了 LiuliX 如何通过 "Prompt as Code" 理念和双层架构，将 AI 从"只会聊天的诗人的"转变为"严谨执行的工程师"。

---

## 1. 核心挑战：不论诗词，只论对错

ChatGPT 擅长写诗，因为诗歌没有标准答案。但数据分析不同：
*   **输入**: `df['price'].mean()`
*   **输出**: 必须是精确的浮点数。

如果 AI 编造了一个列名，或者调用了一个不存在的函数，分析就会崩溃。这就是 LiuliX 致力于解决的核心问题：**如何让概率性的 LLM 产出确定性的分析结果？**

---

## 2. 解决方案 A：双层架构 (L1 Router / L2 Worker)

我们没有试图用一个超级 Prompt 解决所有问题，而是设计了类似 CPU 的流水线架构：

### L1：决策层 (The Router)
*   **职责**: 仅仅做"选择题"，不做"填空题"。
*   **原理**: L1 接收数据摘要，然后从预定义的**能力清单**中选择最合适的工具。
*   **Prompt 示例**:
    > "你是一个数据分析师。根据以下 columns，从 [distribution_analysis, correlation_analysis] 中选择最适合的一个。不要输出任何代码。"
*   **收益**: 极大地限制了 AI 的发散空间，杜绝了"为了回答而回答"的胡编乱造。

### L2：执行层 (The Worker)
*   **职责**: 专注写代码，不关心业务逻辑。
*   **原理**: 接收明确的指令（如"画出 price 列的直方图"）和严格的上下文（列名、类型），输出可执行的 Python/SQL 代码。
*   **收益**: 上下文窗口更小、更专注，代码生成准确率提升 40% 以上。

---

## 3. 解决方案 B：Prompt as Code

在 LiuliX 中，Prompt 不是一段随意的文本，而是一段**代码**。我们强制要求 AI 以 **JSON格式** 进行思考和输出。

### 为什么是 JSON?
自然语言充满了歧义，而 JSON 是结构化的。
*   **Typing (类型约束)**: 我们使用 TypeScript 接口严格定义了 AI 的输出格式。
*   **Validation (校验)**: 如果 AI 返回的 JSON 缺少字段或类型错误，会被前端拦截器直接打回重试，用户甚至感觉不到错误的发生。

```json
// LiuliX 内部协议示例
{
  "thought": "分析价格分布需要排除异常值",
  "code": "df = df[df['price'] < 1000]\nplt.hist(df['price'])",
  "plot_type": "histogram",
  "confidence": 0.95
}
```

---

## 4. 解决方案 C：AST 级代码增强

即使 AI 写出的代码在语法上是对的，逻辑上可能是错的（例如：访问了空的 DataFrame）。

为此，我们开发并开源了 **[LiuliX Code Enhancer](https://github.com/liulix/code-enhancer)**。

这不是简单的正则替换，而是基于 **AST (抽象语法树)** 的深度解析器。它会在代码执行前，自动注入防御性逻辑：

1.  **空值防御**: 自动检测 `df` 是否为空。
2.  **列名检查**: 确保代码中引用的列名真实存在于数据中。
3.  **索引越界保护**: 第一时间捕获 `IndexError` 并转化为友好的提示。

通过 **L1/L2 分层**、**JSON 结构化约束** 和 **AST 代码增强**，我们将 AI 的幻觉率降低到了工业级可用的水平。我们相信，只有建立在坚实工程基础上的 AI，才是值得信赖的生产力工具。
