# ✍️ LiuliX 白皮书写作规范

本文档定义了 LiuliX 用户白皮书（Whitepaper）的写作标准、风格指南与维护规则。所有位于 `whitepaper/` 目录下的文档均需遵循本规范。

---

## 🎯 核心目标

白皮书直接面向**最终用户**（而非开发者），旨在：
1. **建立信任**：透明地解释产品机制（隐私、安全、成本）。
2. **降低门槛**：提供傻瓜式的操作指引（如本地模型部署）。
3. **传递价值观**：强化 "Local-First"、"Zero Cloud Dependency" 的产品理念。

---

## 📝 命名与文件管理

### 1. 命名规则
- **格式**：`序号-分类-标题.md`
- **序号约定**：
  - `01-`: 入门/教程 (Getting Started)
  - `02-`: 政策/限制 (Policies)
  - `03-`: 核心功能 (Features)
  - `10-`: 原理/架构 (Deep Dive)
  - `99-`: 元文档 (Meta)
- **示例**：
  - `01-新手教程-Ollama本地部署指南.md`
  - `10-架构原理-本地优先的数据堡垒.md`

### 2. 目录结构
所有用户可读文档必须存放在根目录的 `whitepaper/zh-CN/` 文件夹中。
*(注：`docs/` 目录主要面向开发者，`whitepaper/` 面向用户)*

## 🎨 写作风格 (Tone & Voice)

### ✅以此为准 (Neutral & Technical)
- **工程师视角**：像写 Technical Spec 一样写文档。专注事实 (Facts) 和机制 (Mechanisms)。
- **克制**：使用"支持"、"提供"、"实现"等中性动词。
- **客观**：即便是优点，也要说明适用边界。
- **示例**：
    - ✅ "本地模式将数据保留在客户端。"
    - ❌ "本地模式为您提供极致的隐私保护！"

### ❌ 避免使用 (No Marketing Fluff)
- **过度承诺**：极致、完美、零风险、100%。
- **营销形容词**：震撼、革命性、重新定义、从零开始。
- **诱导性标点**：避免连续使用感叹号 (!!) 或 Emoji 轰炸。
- **比喻过滥**："数据堡垒"、"隐私长城" (直接说技术原理即可)。

## 🏗️ 标准文档结构

一篇标准的白皮书文档应包含以下部分：

### 1. 标题 (H1)
清晰明确的主题，如 `# ⚠️ API Key 使用说明与限制`。

### 2. 摘要/Intro
一句话说明本文档的目的。

```markdown
本文档详细说明 LiuliX 的数据隐私保护机制与脱敏策略。
```

### 3. 核心内容 (H2 - H3)
- 使用 **表格** 对比不同模式（如 本地 vs 云端）。
- 使用 **代码块** 展示配置示例或 JSON 响应。
- 使用 **Mermaid 图表** (可选) 解释复杂流程，但需保持简单。

### 4. 视觉强调 (Callouts)
善用引用块或 Emoji 列表来强调关键信息：

```markdown
- ✅ **推荐**：使用 Ollama 本地模式
- ⚠️ **注意**：云端模式消耗配额
- ❌ **禁止**：在生产环境使用试用 Key
```

### 5. 常见问题 (FAQ)
以 Q&A 形式预判用户疑问，特别是关于隐私和费用的问题。

### 6. 相关文档
提供交叉链接，形成知识网络。

## 📏 排版规范

1. **中英文混排**：中英文之间**必须**加空格。
   - 正确：使用 Ollama 本地模型
   - 错误：使用Ollama本地模型
2. **数字与单位**：数字前后加空格。
   - 正确：限制 20 次调用
3. **代码引用**：关键术语、配置项、文件路径使用行内代码块 \`\` 包裹。
   - 示例：在 `Settings` 中开启 `Use Local Model`。
4. **链接**：使用相对路径引用其他白皮书文档。

---

## 🔍 数据隐私特别规定

在涉及数据隐私的描述时，必须严格遵守以下术语：

- **本地模式** (Local Mode) = **完全离线** / **零云依赖**
- **云端模式** (Cloud Mode) = **数据上传** (即使是脱敏后)
- **自动脱敏** (Auto Sanitize) = **仅发送元数据** (Metadata Only)
- **原始数据** (Raw Data) = **发送采样数据** (Sampled Data)

**严禁**使用模棱两可的描述误导用户认为云端模式也是离线的。

## 🛠️ 维护流程

1. **变更同步**：代码逻辑变更（如限额策略调整）后，必须在 24 小时内更新对应白皮书。
2. **多语言**：目前以 **中文** 为主，未来支持英文版时需保持结构一致。
3. **版本号**：在文档底部注明最后更新日期。
